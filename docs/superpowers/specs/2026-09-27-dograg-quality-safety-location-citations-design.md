# DogRAG 검색 품질·안전성·거리 검색·보고서 근거 설계

## 목적과 범위

건강 상담의 검색 품질을 측정·개선하고, 근거가 약하거나 긴급성이 있는 질문을 안전하게 처리한다. 사용자가 명시적으로 허용한 브라우저 위치로 실제 직선거리순 병원을 찾고, 보고서 분석의 PDF 근거를 화면에서 확인할 수 있게 한다. 마지막에 실제 모델 API를 호출해 건강 상담과 보고서 분석을 검증한다. 기존 홈 화면·질문 분기 수정과 미커밋 파일은 보존한다.

이 작업은 원천 Q&A의 질병명을 추측해 재분류하거나, 병원 영업 여부·도로 이동시간을 추정하거나, 앱을 배포하지 않는다. 의료적 진단이나 수의사 검토를 대체하지 않는다.

## 현재 상태와 설계 원칙

- `data/df.csv`는 19,206행이며 `meta.disease=기타`가 14,774행(76.9%)이다. `data/df_val.csv`는 561행이다. README의 건수는 이 파일들과 다르다.
- 기존 평가 출력의 `hit@3=0.20`은 validation 50건에서 연령·진료과·질병 메타데이터의 완전 일치로 계산한 값이다. 의료 정확도 지표로 해석하지 않는다.
- 건강 Chroma `pet_care`는 19,206건, 보고서 `pet_analysis_1024`는 127건이다. Chroma 영속 파일은 조회 때도 바뀔 수 있으므로 모든 검색·평가는 임시 복사본에서 실행한다.
- `run_report_analysis()`는 현재 문자열만 반환하고 분석 경로의 `evidence_rows`는 비어 있다. 보고서 PDF 청크의 `page`는 1부터 시작한다.
- “가까운 병원”은 현재 `LIMIT 1`일 뿐 거리 계산이 없다. 병원 DB 5,448건의 좌표는 EPSG:5174이며 지도 표시는 EPSG:4326으로 변환한다.

## 1. 데이터 품질과 건강 검색

원본 CSV와 `data/chroma_db`는 수정하지 않는다. 재실행 가능한 감사 명령은 필수 컬럼·결측·중복·공백/표기 불일치와 질병·진료과 분포를 기록한다. `기타`를 자동으로 다른 질병명에 할당하지 않는다. 명백한 공백 정규화 같은 표기 정리는 파생 결과에만 적용하며 원본 값을 추적 가능하게 유지한다.

검색 후보는 기존 벡터 검색을 기준선으로 두고, 더 큰 후보 집합을 받은 뒤 질문과 Q&A 문서의 문자 단위 어휘 일치를 이용해 재정렬하는 방식을 실험한다. 추가 모델이나 외부 서비스를 필수로 하지 않는다. 동일한 고정 validation 집합에서 기존 방식과 후보 방식을 비교하고, 전체 및 `기타`/비`기타` 분리 `hit@3`, `MRR@3`, 검색 실패 건수를 기록한다. 이 지표는 검색 참고값이며 안전성·의학적 정확도를 보장하지 않는다. 후보 방식이 전체 `hit@3`를 개선하고 비`기타` 집합을 악화시키지 않을 때만 기본 앱에 적용한다. 그렇지 않으면 기존 검색을 유지하고 결과를 보고한다.

## 2. 건강 답변 안전성

건강 경로는 검색 결과가 없거나 검증 질문/무관 질문에서 정한 보수적 관련도 기준에 미달하면 모델을 호출하지 않고 근거 부족을 명확히 알린다. 관련도 값은 모델별 의미를 확인한 후에만 임계값으로 사용하며, 검증되지 않은 수치를 임의로 고정하지 않는다. 임계값을 신뢰할 수 없으면 빈 결과 방어만 적용하고 제한을 문서화한다.

호흡곤란, 의식 소실·쓰러짐, 발작, 독성 물질 섭취, 반복적인 헛구역질 등 명백한 긴급 신호는 일반 답변보다 앞에 진료 권고를 표시한다. 단순 ‘구토’ 같은 단어 하나만으로 응급 판정을 하지 않는다. 문구는 [VCA의 반려견 응급 안내](https://vcahospitals.com/premier/know-your-pet/common-emergencies-in-dogs) 및 [AVMA 응급 안내](https://ebusiness.avma.org/files/productdownloads/mcm-client-brochures-pet-first-aid-2023.pdf)를 근거로 하며 진단명·약물·자가 처치 지시를 생성하지 않는다. 근거 목록과 안전 안내는 UI에서도 구별해 표시한다. 오탐·누락을 확인하는 한국어 테스트를 포함한다.

## 3. 현재 위치 기반 병원 거리 검색

Streamlit 1.61의 `st.components.v2`로 ‘현재 위치 사용’ 버튼을 제공한다. 버튼을 누를 때에만 브라우저 `navigator.geolocation.getCurrentPosition()`을 호출한다. 권한 거부·타임아웃·미지원·HTTPS가 아닌 배포 상황에는 오류를 설명하고 기존 지역 선택 검색을 계속 제공한다. 위치 좌표는 현재 세션의 계산에만 사용하며 SQLite·파일·로그·대화 이력에 저장하지 않는다. 브라우저 위치 API는 HTTPS와 명시적 권한이 필요하다. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition), [Streamlit Components v2](https://docs.streamlit.io/develop/api-reference/custom-components/st.components.v2.component).

좌표를 받은 경우 EPSG:5174 병원 좌표를 WGS84로 변환하고 Haversine 직선거리를 계산해 가까운 순서로 정렬한다. 화면에는 병원명·주소·거리(km)·지도 위치를 표시하고 ‘직선거리이며 이동거리/소요시간과 다름’을 명시한다. 잘못된 좌표와 결측은 제외한다. 챗봇의 ‘가까운 병원’ 요청도 같은 계산을 사용한다. 좌표 없이 들어온 ‘가까운’ 질문은 임의의 첫 병원을 가장 가깝다고 표시하지 않고 위치 사용 또는 지역 검색을 안내한다. 지역 검색·병원 개수·병원 하나만 요청의 기존 계약은 유지한다. 위치 UI 테스트는 실제 사용자의 위치를 요청하지 않고 모의 좌표로 수행한다.

## 4. 보고서 근거와 PDF 페이지

보고서 분석은 답변과 검색된 청크의 `page`, 텍스트 발췌, 문서명을 구조화해 반환한다. 기존 분석 도구의 텍스트 반환 계약은 필요한 범위에서 유지한다. UI는 각 근거를 페이지 번호와 발췌문으로 보여주고, 요청된 페이지를 로컬 PDF에서 PyMuPDF로 렌더링해 미리보기로 제공한다. 페이지가 없거나 PDF가 없으면 오류 대신 근거 텍스트와 안내를 보여준다. 노트북에 기록된 과거 절대 `source_path`는 링크로 사용하지 않고 저장소의 PDF를 사용한다. 청크의 페이지 번호는 1-based이며 PDF 페이지 인덱스로 변환할 때만 1을 뺀다.

## 검증과 완료 기준

1. 각 새 행동의 실패하는 회귀 테스트를 먼저 실행하고 최소 구현 뒤 통과시킨다. 기존 전체 테스트도 통과해야 한다.
2. 데이터 감사 결과와 동일 validation 집합의 기존/후보 검색 지표를 제시한다. 성능 개선이 없으면 검색 기본값을 바꾸지 않았음을 명시한다.
3. 원본 Chroma를 복사한 테스트에서 건강·보고서 검색을 실행한 뒤 원본 Git 상태가 변하지 않았는지 확인한다.
4. 건강 경로의 근거 부족·응급 신호, 병원 거리 정렬·권한 거부 대체 경로, 보고서 페이지 경계·미리보기를 단위 및 Streamlit 화면 테스트로 확인한다. 브라우저 위치 권한의 실제 작동은 HTTPS 배포가 없는 로컬 검증의 한계로 별도 보고한다.
5. 사용자 승인에 따라 실제 OpenAI API로 건강 질문과 보고서 질문을 각각 최소 1회 호출해 경로·근거·답변을 확인한다. 이때 검색된 Q&A/보고서 발췌 일부가 외부 API로 전송된다. 테스트 질문은 합성하며, 검색 근거에 개인식별정보가 있는지 호출 전에 점검한다. 민감한 원문과 API 키를 출력·로그·커밋하지 않는다. 호출이 정책·네트워크·모델 제한으로 실패하면 우회하지 않고 미검증으로 보고한다.
6. README의 데이터 건수·기능 설명·테스트 명령을 실제 결과에 맞춰 갱신한다. `git diff --check`와 최종 Git 상태를 확인하고 기존 미커밋 변경을 보존한다.

## 의도적 제외와 위험

- 질병명 자동 재라벨링, 원본 Chroma 재색인, 외부 지오코딩/도로 경로 API, 실시간 병원 영업 여부, 앱 배포는 제외한다.
- 어휘 재정렬은 질병명 검색을 도울 수 있지만 문장 의미를 놓칠 수 있다. 따라서 고정 집합 비교와 비`기타` 악화 방어가 선행된다.
- 응급 키워드 규칙은 완전한 분류기가 아니다. 미탐 가능성을 안내하고 전문 수의사의 검토를 후속 운영 요건으로 둔다.
- 실제 모델 호출은 비용과 데이터 외부 전송이 발생한다. 승인된 최소 질문 수만 호출한다.
