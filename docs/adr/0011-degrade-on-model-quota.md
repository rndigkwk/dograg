# ADR-0011: 모델 사용 한도가 떨어지면 검색 결과로 버티고, 평가와 운영의 키를 나눈다

- **상태:** 채택 (2026-10-19~20, #238·#242·#244·#240·#239)
- **관련:** ADR-0007(검색 위치: 건강 검색이 OpenAI 없이 도는 이유), [slo.md](../slo.md#모델-한도-소진-2026-10-19)

## 맥락

- **무슨 일이 있었나:** 2026-10-19 오후 OpenAI 프로젝트가 설정한 사용 금액 한도에 닿았다(429 `insufficient_quota`, `project_spend_limit_exceeded`). 다음 날 오후 초기화될 때까지 인사말을 포함한 모든 질문이 "답변을 만드는 중에 문제가 생겼습니다"로 끝났고, 배포 점검이 실패 이슈를 열었다(#237).
- **원인:** 운영 API, CI(병합 게이트·주간 회귀), 로컬 평가가 **같은 프로젝트 키**를 썼다. 그날 평가와 확인으로 수백 번 부른 호출이 운영 한도를 다 썼다.
- **빈틈 하나 더:** 데이터 버전만 바꾼 PR(#236)은 병합 게이트를 건너뛰었다. 답변 경로 목록에 `src/private_data.py`가 없었기 때문이다.
- **쓸 수 있는 것:** 모든 기능이 모델에 기대지는 않는다.
  - 건강 검색은 질문 벡터를 서버 안 ko-sroberta가 만들고, 상담은 Supabase, 지침은 메모리에서 찾는다.
  - 시설 찾기, 진료비, 관리 일정은 모델을 쓰지 않는다.
  - 보고서 분석은 검색에도 OpenAI 임베딩을 쓴다.

## 결정

1. **한도 오류일 때만 낮춰 동작한다** (`src/model_outage.py`).
   - 예외 사슬에서 `RateLimitError` + quota 표시를 찾는다. 단순 속도 제한과 다른 오류는 지금처럼 오류 하나로 알린다.
   - 챗봇(API #238, Streamlit #242)은 "AI 서비스 이용 한도가 다 되어 답변을 쓰지 못합니다"라고 알린다. 가까운 상담 사례(유사도 하한 이상)와 지침은 **답 없이** 근거로 보여 준다.
   - 자료와 먼 질문, 다른 동물 질문은 안내만 보인다. 응급 징후 규칙은 그대로 돈다.
   - 안내는 화면마다 그 화면에 있는 기능만 적는다(#244).
   - 방문 준비 보고서는 "이어서 만들기"를 보이지 않는다. 같은 이유로 다시 실패하기 때문이다.
2. **키를 나눈다** (#240, 코드 변경 없음). 운영은 GCP Secret Manager, CI는 GitHub secret, 로컬은 `.env`에서 키를 읽는다. CI와 로컬에는 **별도 OpenAI 프로젝트**(별도 한도)의 키를 넣는다.
3. **데이터 변경도 게이트를 거친다** (#239). 답변 경로 목록에 `src/private_data.py`와 `src/tools/care_guides.py`를 더했다.

## 결과

- **얻는 것:**
  - 한도가 떨어져도 챗봇이 멈추지 않는다. 장애 중 운영에서 "안내 + 윤리 가이드라인 39쪽 + 상담 3건"이 나오는 것을 확인했다.
  - 키를 나누면 평가 비용이 운영을 멈추지 못한다.
- **감수하는 것:**
  - 낮춘 상태에서는 답이 아니라 자료 목록이다. 보호자가 직접 읽어야 하고, 보고서 분석은 쓸 수 없다.
  - 키 분리는 소유자가 프로젝트를 만들어야 끝난다(2026-10-20 현재 아직).
- **다시 검토할 조건:**
  - 다른 모델 제공자를 대체 경로로 둘 만큼 장애가 잦을 때
  - 보고서 검색을 서버 안 임베딩으로 옮길 때(그러면 보고서도 낮춘 상태에서 쓸 수 있다)
  - 키 분리 뒤에도 운영 한도가 닿을 때: 그때는 사용량 자체의 문제다.
