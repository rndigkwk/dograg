# ADR-0004: 두 배포(Streamlit Cloud, Cloud Run)에 공유 DB를 두지 않음

- **상태:** 채택 (2026-10-12 #94, 2026-10-13 소급 작성)

## 맥락
- 같은 코드를 Streamlit Community Cloud와 Cloud Run에서 함께 운영한다. 한쪽이 멈춰도 다른 쪽이 돌게 하는 것이 목적이다.
- 대화 기록과 반려견 정보는 민감한 상담 내용이다. 이 서비스는 로그인 없이 쓴다.
- Supabase 같은 공유 Postgres를 넣을지 검토했다(#94).

## 결정
공유 DB를 두지 않는다. 상태마다 둘 곳을 따로 정한다.

| 상태 | 둘 곳 |
| --- | --- |
| 대화 기록, 반려견 정보 | 사용자 브라우저 저장소 |
| 상담·시설·진료비 데이터와 벡터 DB | 이미지 안(Cloud Run). Streamlit Cloud는 비공개 HF 데이터셋에서 받는다. 둘 다 리비전 고정 |
| 피드백, 실행 기록 | Langfuse (환경 이름으로 배포 구분) |
| 방문 보고서 되묻기 중인 실행 | 서버 메모리, 최대 30분. Cloud Run은 session affinity를 쓰고 최대 인스턴스는 2 |

**뺀 대안:** 공유 Postgres(Supabase)
- 장애 지점이 하나 늘어난다. DB가 멈추면 두 배포가 함께 멈춘다.
- 배포 사이에 대화를 옮기려면 로그인과 상담 내용 서버 저장이 필요하다. 이건 설계 원칙("서버에는 남지 않습니다")과 부딪힌다.

## 결과
- **얻는 것:** 두 배포가 서로 독립적으로 돈다. 상담 내용을 서버에 저장하지 않는다.
- **감수하는 것:**
  - 한 배포에서 나눈 대화가 다른 배포에서 보이지 않는다.
  - 되묻기 중인 실행은 인스턴스가 바뀌면 이어 갈 수 없다.
- **다시 검토할 조건:**
  - 로그인(여러 기기에서 대화 이어 보기)을 넣기로 할 때. 그때는 Supabase(인증 + Postgres)와 LangGraph Postgres 체크포인터가 후보다. 보관 기간·삭제·암호화를 먼저 정한다.
  - 벡터 저장소를 외부 DB(예: pgvector)로 옮기기로 할 때. ADR-0003과 함께 다시 본다.
