# ADR-0005: 리랭커를 쓰지 않음

- **상태:** 채택 (2026-10-08, 2026-10-13 소급 작성)

## 맥락
- 하이브리드 후보 안에 쓸모 있는 문서가 있는 비율은 99%였다. 그런데 상위 3건에는 72%만 들어왔다(useful@3, 100문항). 순서만 바꿔도 오를 여지가 크다.
- 제약: CPU 2코어, 메모리 690MB 보장, torch 없음. 검색은 답변 전 단계라 몇 초 안이어야 한다.

## 결정
리랭커를 쓰지 않는다. 하이브리드 RRF 순서(ADR-0002)를 그대로 쓴다.

**고려한 후보와 뺀 이유:**

| 후보 | 결과 | 뺀 이유 |
| --- | --- | --- |
| 상업 사용 가능한 ONNX 리랭커 2종 | useful@3 0.72 → 0.69, 0.45 | 오히려 나쁘다 |
| 나은 리랭커 1종 | 0.76 | 비상업 라이선스, 질문당 8초, 메모리 약 0.5GB 추가 |
| `BAAI/bge-reranker-base` | 질문당 13.9초, 메모리 +1,311MB | 느리고 무겁다. 순서도 나빴다 |
| Qwen3-Reranker-0.6B (교안) | 품질 같음, 질문당 166초, 최고 4.9GB | 배포 불가 |
| CRAG 근거 평가 순서로 재정렬 | 후보 5건에서 개선 없음. 12건이면 +4문항(p=0.45) | 통계적으로 의미 없음. 토큰 1.7배, 지연 +0.9초 |
| 후보 수 5 → 8 | 기본 관리 질문 20/3/7 그대로 | 토큰 +19~24% |

## 결과
- **얻는 것:** 검색 지연과 메모리가 작게 유지된다.
- **감수하는 것:** 상위 3건과 후보 전체 사이의 차이(0.72 대 0.99)를 남겨 둔다.
- **다시 검토할 조건:**
  - 앱이 Cloud Run(2GiB)만 쓰게 되거나, 외부 리랭크 API를 쓸 수 있게 될 때(질문이 외부로 나감, 비용)
  - 한국어로 학습된 가벼운 리랭커(수백 MB 이하, 상업 사용 가능)가 나올 때. 같은 100문항으로 잰다.
    - 2026-10-21: 배포 제약을 두지 않고 GPU에서 `bge-reranker-v2-m3`·`-ko`를 지금 운영 검색 후보에 붙였다. 검증 100 0.84 → 0.86(p=0.63), `기타` 0.79 → 0.78, CPU 1스레드 질문당 11.7초. **결정은 그대로다**([wiki](../wiki/retrieval-experiments.md) "GPU 리랭커").
