# ADR-0002: 검색 전략으로 Dense + BM25(Kiwi) 하이브리드, RRF 합치기 사용

- **상태:** 채택 (2026-09-28 건강, 10-08 보고서, 2026-10-13 소급 작성)

## 맥락
- 보호자 질문과 상담 글은 단어가 잘 겹치지 않는다. 예: "오줌 색" 대 "혈뇨". 반대로 질병명·약 이름처럼 정확한 단어가 중요한 질문도 있다.
- 보고서 질문은 수치·표 이름을 묻는 경우가 많다.
- 제약: CPU, 메모리 690MB 보장. 검색은 답변 생성 전 단계라 짧아야 한다.

## 결정
- **두 검색기를 함께 쓴다.**
  - 문장 임베딩(Dense, ADR-0001)
  - BM25: Kiwi 명사 토큰
  - 각각 후보 12건을 가져와 RRF로 합친다.
  - 건강과 보고서 모두 같은 방식이다.
- **질문에서 추론한 메타데이터 필터는 쓰지 않는다.**
- 근거 평가(CRAG)는 합친 결과의 상위 5건을 본다.

**고려한 후보와 뺀 이유:**

| 후보 | 결과 | 뺀 이유 |
| --- | --- | --- |
| Dense만 | 건강 hit@3 0.2264 | 하이브리드 0.2620 |
| BM25만 | 건강 hit@3 0.2496 (RRF 가중치 실험의 BM25 단독) | 뜻이 같고 단어가 다른 질문을 놓친다 |
| 보고서 Dense만 | 기준 답과 맞는 답 23/36 | 하이브리드 30/36 (McNemar p=0.016) |
| RRF 가중치 조정 | 효과 없음 | 기본 RRF 유지 |
| 연령·진료과 필터 | hit@3 0.141 | 필터를 빼자 0.264. 말뭉치 라벨이 질문 본문과 34%·59%만 맞았다 |
| 질문 유형마다 다른 전략 | 측정하지 않음 | 건강·보고서 모두 하이브리드가 나았다. 유형별 분기는 분류 오류라는 새 위험을 만든다 |

## 결과
- **얻는 것:** 짧은 구어체와 정확한 용어 질문을 함께 다룬다.
- **감수하는 것:**
  - BM25 색인을 앱 메모리에 올린다. 토큰 캐시로 첫 준비를 132.8초에서 2.2초로 줄였다.
  - 동점 처리 규칙이 결과를 조금 바꾼다. 문서 ID 문자열 순서다.
- **다시 검토할 조건:**
  - 질문 유형(증상·약·시설·통계 등)별로 전략을 나눠 잰 표에서, 특정 유형이 한 전략에서 유의하게 나을 때
  - 저장소가 BM25(전문 검색)를 제공하는 쪽으로 바뀔 때. 예: pgvector + 한국어 전문 검색. 같은 평가로 다시 잰다.
  - 문서 수가 크게 늘어 메모리 안 BM25가 한도를 넘을 때

**기록:** [wiki/retrieval-experiments.md](../wiki/retrieval-experiments.md) 실험 1·4·13, [improvement-log.md](../improvement-log.md) 1절

## 보충 측정 (2026-10-13)
결정은 바꾸지 않는다. "질문 유형마다 다른 전략: 측정하지 않음"을 측정했다([wiki/retrieval-experiments.md](../wiki/retrieval-experiments.md) "질문 유형마다 다른 검색 전략").
- **유형별 라우터는 만들 이유가 없다.** 길이 × 이름 포함으로 나눈 4개 유형, 220문항에서 유형별로 고른 상한은 0.836이다. 하이브리드는 0.809이고 p=0.29다.
- **미세조정 뒤에는 dense만(0.827)과 하이브리드(0.809)도 차이가 없다**(p=0.56). 그래서 다시 검토할 조건을 하나 더한다.
  - 건강 BM25를 빼서 메모리를 줄이고 싶을 때, 더 큰 세트와 CRAG 60으로 dense만 써도 나빠지지 않는지 확인한 뒤 새 ADR을 쓴다.
