# ADR-0006: Cloud Run 지역은 서울(asia-northeast3) 유지

- **상태:** 채택 (2026-10-13)

## 맥락
- OpenAI와 Langfuse는 미국에 있다. Streamlit Community Cloud도 미국 오리건(GCP `us-west1`)으로 추정한다. 근거는 ADR-0003에 있다.
- Langfuse 기록에서 같은 근거 판정 호출의 p50이 Cloud Run 서울 1,989ms(14회), Streamlit Cloud 1,537ms(68회)였다. 서울 서버가 OpenAI 호출마다 손해를 볼 수 있다.
- 사용자는 한국에 있다. 서버를 미국에 두면 화면 조작과 페이지 로딩마다 태평양 왕복이 붙는다.

## 결정
Cloud Run을 서울에 둔다. Supabase도 같은 서울 지역을 쓴다.

**측정** (`scripts/compare_deployment_latency.py`):
- 같은 이미지를 `us-central1`에 임시 서비스로 띄웠다. Streamlit Cloud와 다른 지역을 골랐다(같은 장애에 함께 멈추지 않게).
- 한국 PC 브라우저에서 질문 12개를 두 바퀴 보냈다(건강 6, 시설 2, 보고서 2, 진료비, 날짜). 서비스 순서는 번갈아 바꿨고, 콜드 스타트는 미리 깨워 제외했다.

| 중앙값 | 서울 | us-central1 |
| --- | ---: | ---: |
| 첫 화면 | **2.2초** | 3.7초 |
| 첫 글자 | **5.1초** | 5.3초 |
| 답변 완료 | **8.6초** | 9.4초 |
| 건강 / 보고서 답변 완료 | 10.1 / 10.9초 | 10.6 / 8.8초 |
| 미국이 더 빠른 질문 | | 8/24 |

- OpenAI와 가까워져 얻는 시간보다, 한국 사용자와 서버 사이 왕복에서 잃는 시간이 더 컸다.
- 보고서 답변만 미국이 빨랐다(질문 2개 × 2번). OpenAI 호출과 출력이 많은 경로라 그럴 수 있지만, 표본이 작다.

## 결과
- **얻는 것:** 첫 화면과 답변 완료가 빠르다. Supabase(서울)와 왕복 6.8ms다.
- **감수하는 것:** OpenAI 호출마다 태평양 왕복이 붙는다.
- **다시 검토할 조건:**
  - 사용자 대부분이 미국에 있게 되면
  - OpenAI 호출이 지금보다 훨씬 많아지면(예: 다단계 에이전트를 기본으로 쓸 때). 같은 스크립트로 다시 잰다.
  - 임시 서비스 `ragdog-region-test`(us-central1)는 측정 뒤 지운다.
