# ADR-0009: 지난 상담 기억은 사용자가 고른 "상담 노트"로, 사용자 계정 테이블에

- **상태:** 제안 (2026-10-17). 아래 "정할 것"에 소유자가 답하면 채택하고 구현한다.
- **관련:** Day 52 Mem0(서버 쪽 기억, [lecture-review.md](../wiki/lecture-review.md)), ADR-0008 P4(로그인과 계정 기록)

## 맥락

**지금 기억하는 것은 세 가지다.**
1. **우리 아이 정보:** 품종, 나이, 체중, 지병, 복용약, 알레르기. 답변 뒤 새 사실을 제안하고, 보호자가 눌러야 저장한다(`src/tools/profile.py`).
2. **한 대화 안의 요약:** 최근 6턴은 원문으로, 오래된 턴은 600자 요약으로 넘긴다(`src/tools/history.py`). 대화가 바뀌면 이어지지 않는다.
3. **대화 기록:** 로그인 사용자의 대화 20개를 `ragdog_user_threads`에 저장한다. 브라우저가 사용자 JWT로 읽고 쓰고, RLS가 자기 행만 허용한다. API 계정(`ragdog_app`)에는 권한이 없다.

**빠진 것은 지난 대화의 내용이다.** 예를 들어 지난주 "보리가 설사를 해요" 상담에서 "이틀 넘으면 병원"이라는 안내를 받았다고 하자. 오늘 새 대화에서 "또 설사해요"라고 물으면 답변은 그 일을 모른다. 지병이나 복용약처럼 오래 가는 사실은 1번이 다루지만, 언제 무슨 증상이 있었고 무엇을 안내받았는지는 어디에도 이어지지 않는다.

**지켜야 할 것**
- 건강 정보다. 동의한 사용자만 쓰고, 무엇을 기억하는지 보여 주고, 하나씩이든 전부든 지울 수 있어야 한다(lecture-review의 조건).
- API는 상태를 갖지 않는다. 사용자 기록을 서버 코드가 대신 읽지 않는다(ADR-0008, RLS).
- 기억은 근거가 아니다. 답변의 근거는 여전히 상담 사례와 보고서이고, 기억은 보호자가 알려 준 맥락으로만 쓴다.
- 비용과 지연이 질문마다 늘지 않아야 한다.

## 결정 (제안)

**보호자가 고른 "상담 노트"만 기억한다.** 노트는 대화 하나를 2~3문장으로 줄인 것이다. 사용자 계정 테이블에 두고, 새 질문에 브라우저가 함께 보낸다.

### 1. 노트 만들기 (보호자가 누를 때만)
- 건강 답변 아래에 "이 상담 기억하기" 버튼을 둔다. 지금의 "우리 아이 정보 저장" 제안과 같은 자리에 같은 방식으로 둔다.
- 누르면 `POST /memory/note {question, answer}`가 모델을 1번 불러 노트를 만든다.
  - 노트에는 날짜, 증상·상황, 받은 안내, 다시 볼 조건(예: "이틀 넘으면 병원")을 300자 안으로 담는다.
  - 개인정보는 기존 가림(`src/pii.py`)을 거친다.
- 저장하기 전에 노트를 보여 주고, 보호자가 고쳐 쓰거나 취소할 수 있다.
- 자동으로 만들지 않는다. 질문마다 드는 비용이 없고, 기억할지는 보호자가 정한다.

### 2. 저장 (사용자 계정, RLS)
- 새 테이블 `ragdog_user_notes`를 둔다. 열은 `user_id`, `note_id`, `note`(300자 이하), `created_at`, `thread_id`(어느 대화에서 왔는지, 선택)다.
  - `ragdog_user_threads`와 같은 규칙을 따른다: 자기 행만, `authenticated`에만 권한, `ragdog_app`과 `anon`에는 없음.
  - 계정당 최대 30개(트리거)이고, 계정을 지우면 함께 지워진다(`on delete cascade`, `delete_my_account()`).
- 로그인하지 않은 사용자에게는 v1에서 제공하지 않는다. 브라우저 저장은 기기를 바꾸면 사라지고, 공용 PC에 건강 기록이 남는다.

### 3. 쓰기 (새 질문마다, 추가 호출 없음)
- 설정에서 "지난 상담 기억 사용"이 켜져 있으면, 브라우저가 최근 노트 5개(최대 1,500자)를 `/chat` 요청의 `notes`로 보낸다.
- API는 노트를 건강 답변 프롬프트에 "[보호자가 저장한 지난 상담 기록]" 칸으로 넣는다(우리 아이 정보처럼).
  - 근거 목록에는 넣지 않는다.
  - 답변에서 "지난번 기록에 따르면"처럼 기록이라는 것을 밝히게 한다.
- 검색어에는 넣지 않는다(v1). 넣으면 좋은지는 따로 잰다. Day 52에서 요약을 검색에 넣었을 때처럼 측정한 뒤 정한다.
- 서버는 노트를 저장하지도 기록하지도 않는다. Langfuse에는 지금처럼 가린 길이만 남는다(`src/tracing.py`).

### 4. 보기와 지우기
- 계정 메뉴에 "기억" 화면을 둔다. 노트 목록(날짜순), 하나씩 지우기, 모두 지우기, "기억 사용" 켜기·끄기가 있다.
- 기본값은 **꺼짐**이다. 처음 "이 상담 기억하기"를 누를 때 무엇을 저장하고 어떻게 쓰는지 한 번 설명하고 켤지 묻는다.

## 검토한 다른 방법

| 방법 | 장점 | 쓰지 않는 이유 |
| --- | --- | --- |
| Mem0처럼 매 턴 자동 추출 + 서버 벡터 검색 | 보호자가 할 일이 없다 | 질문마다 모델 호출이 늘고, 서버가 건강 기록을 모은다. 무엇이 기억됐는지 보호자가 모르기 쉽다 |
| 지난 대화 20개를 통째로 검색 | 노트를 만들 필요가 없다 | 대화가 길어 프롬프트가 커지고, 관계없는 대화가 섞인다. 지운 대화와 기억의 관계가 모호하다 |
| 우리 아이 정보에 "최근 증상" 칸 추가 | 구현이 가장 작다 | 날짜와 안내가 함께 남지 않는다. 증상은 지나가는 것이라 계속 남기면 틀린 정보가 된다 |

## 결과

**좋아지는 것**
- "지난번 설사가 다시 시작됐어요" 같은 이어지는 상담에 맥락이 생긴다.
- 보호자가 고른 것만, 보이는 곳에, 지울 수 있게 남는다.
- 질문당 비용과 지연이 늘지 않는다. 모델 호출은 노트를 만들 때 1번뿐이다.

**나빠지는 것과 위험**
- 노트가 틀리거나 오래되면 답이 그쪽으로 끌릴 수 있다. 그래서 프롬프트에서 "기록"이라고 밝히게 하고, 노트에 날짜를 넣고, 30일이 지난 노트는 "오래된 기록"으로 표시한다.
- 화면이 하나 늘고(기억 관리), DB 테이블과 RLS 검사가 하나 늘어난다.

**구현 전에 잴 것** (모델 호출 약 40번, 실행 전에 다시 알린다)
- 이어지는 상담 10개를 만든다. 지난 노트가 있어야 좋은 답이 되는 경우(재발, 복용약 반응 등)와, 노트가 관계없는 경우를 섞는다.
- 노트 있음·없음으로 답변을 만들어 두 가지를 판사가 본다.
  - 지난 기록을 알맞게 반영했는가
  - 기록에 없는 일을 지어내지 않았는가
- 관계없는 노트가 답을 흐리지 않는지도 함께 본다.
- RLS는 `user_records_test.sql`처럼 남의 노트를 읽고 쓰고 지울 수 없는지 확인한다.

**다시 검토할 조건**
- 노트를 거의 만들지 않으면(로그인 사용자의 5% 미만) 화면을 줄이고 "우리 아이 정보"에 합친다.
- 노트가 30개로 부족하다는 요청이 생기면, 그때 노트 검색(관련 노트만 보내기)을 잰다.

## 정할 것 (소유자)
1. 기본값: 꺼짐(추천) / 켜짐
2. 노트 만들기: 버튼을 눌러야 만들기(추천) / 대화가 끝나면 자동 제안
3. 로그인하지 않은 사용자: v1에서 제외(추천) / 브라우저에만 저장해 제공
