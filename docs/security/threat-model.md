# 위협 표와 레일 (2026-10-21, 교안 day64 반영)

교안 day64(가드레일 통합, 실행 레일과 최소 권한)의 틀로 라그도그를 다시 본 표다. 무엇을 지키는지는 [README.md](README.md)에, 평가 결과는 [wiki/safety-and-evidence.md](../wiki/safety-and-evidence.md)에 있다.

## 1. 위험한 세 요소 (lethal trifecta)

개인 데이터, 밖에서 들어온 글, 밖으로 보내는 수단이 한 곳에 모이면 숨은 지시 하나로 개인 데이터가 밖으로 나갈 수 있다. 라그도그에서 셋이 어디서 만나는지와, 끊어 둔 자리다.

| 요소 | 라그도그에 있는 것 | 끊어 둔 자리 |
| --- | --- | --- |
| 개인 데이터 | 질문 속 전화번호·주소, 반려견 정보, 지난 상담 노트, 로그인 계정의 대화 | 모델에 보내기 전에 가린다(`src/pii.py`). 노트는 본인 것만 브라우저가 보낸다(RLS). 서버는 대화를 저장하지 않는다 |
| 밖에서 들어온 글 | 보호자 질문과 대화 기록, 반려견 정보 칸, 지난 상담 노트, 검색된 상담·지침·보고서 | 프롬프트가 그 안의 지시를 따르지 말라고 한다. **검색 레일**(`src/untrusted.py`)이 봇에게 내린 지시 모양이 든 상담·지침 조각·노트를 모델이 읽기 전에 뺀다 |
| 밖으로 보내는 수단 | 답변 속 링크, OpenAI·Langfuse 호출 | 답변 속 링크는 **우리 자료에 있는 주소만** 남긴다(`src/guardrails.py`). OpenAI에는 가린 글만, Langfuse에는 길이만 간다 |

셋을 모두 가진 경로는 없다. 모델이 고를 수 있는 "밖으로 보내는 도구"(메일, 웹 요청, 쓰기)가 없기 때문이다.

## 2. 경로와 도구의 위험도

교안의 "도구마다 위험도를 나누고, 위험할수록 검사를 겹친다"를 라그도그의 경로에 맞췄다. **모델이 데이터를 바꾸거나 돈이 나가는 도구는 하나도 없다.** 그래서 사람 승인(HITL)과 실행 레일 미들웨어는 필요 없다.

| 경로·도구 | 모델이 정하는 것 | 위험도 | 검사 |
| --- | --- | --- | --- |
| 건강 상담 검색 | 검색어 | 낮음(읽기) | 검색 레일, 근거 평가(CRAG), 근거가 없으면 보류 |
| 돌봄 지침 검색 | 검색어 | 낮음(읽기) | 검색 레일, 유사도 기준(0.52) |
| 시설 검색 | SQL 한 문장 | 중간 | `validate_sql()`: SELECT만, 한 문장, `hospital` 표만. 읽기 전용 SQLite, 3초·1,000행 |
| 진료비 | 없음(규칙과 표) | 낮음 | 모델을 부르지 않는다 |
| 보고서 검색 | 검색어, 하위 질문 | 낮음(읽기) | 근거 평가 |
| 방문 준비 팀 | 조사 과제, 검색어 | 중간(비용) | 보고서 하루 2개·세션 3번, 라운드 상한, 검수 |
| 기억 제안 | 반려견 정보 후보 | 낮음 | 제안만 한다. 저장은 보호자가 누를 때 브라우저가 한다 |
| 피드백·데이터 공백 저장 | 없음(앱이 쓴다) | 낮음 | 가린 문장만, API 계정만, 3년 뒤 삭제 |

교안의 최소 권한 세 겹을 라그도그에 대 보면 이렇다.
- **기능:** 모델에게 쓰기 도구를 주지 않는다.
- **권한:** 누구의 데이터인지는 대화가 아니라 토큰에서 읽는다(RLS, `src/auth.py`).
- **자율성:** 비용이 드는 보고서는 한도로 묶는다.

## 3. 레일 배치

| 자리 | 막는 것 | 방법 | 모델 호출 |
| --- | --- | --- | --- |
| 입력 | 질문 남용 | 질문 한도(`src/rate_limit.py`) | 없음 |
| 입력 | 개인정보 | 가림(`src/pii.py`) | 없음 |
| 입력 | 범위 밖 요청 | 라우터 → 고정 문구(#106) | 라우터 규칙에 안 걸린 질문만 1번 |
| 입력 | 다른 동물 질문 | 검색 전에 보류(`other_species`) | 없음 |
| 검색 | 상담·지침·노트 속 숨은 지시 | 정규식, 문서를 뺀다(`src/untrusted.py`) | 없음 |
| 검색 | 엉뚱한 근거 | 근거 평가(CRAG), 유사도 하한 | 1번 |
| 출력 | 위기 신호(자해, 따라가고 싶다) | **위기 상담 번호 109·1577-0199를 답 맨 앞에**(`src/guardrails.py`). 보류, 범위 밖, 질문 한도 초과에도 붙는다 | 없음 |
| 출력 | 응급 신호 | 응급 안내와 가까운 병원(`src/health_safety.py`) | 없음 |
| 출력 | 우리 자료에 없는 링크 | "(링크 생략)"으로 바꾼다 | 없음 |
| 출력 | 근거에 없는 내용 | 생성 프롬프트 규칙. 인용 검증은 다음 PR | (다음 PR) |

교안의 원칙 중 따른 것:
- 싼 검사를 앞에 둔다.
- 답을 고치는 검사는 맨 뒤에 둔다. 위기 안내를 붙이는 일과 링크를 지우는 일은 답이 다 만들어진 뒤에 한다.
- 고친 것은 이름을 남긴다. 결과의 `guards`에 남고, 요청 요약 로그(`src/request_log.py`)와 Langfuse 실행 기록에서 셀 수 있다.

## 4. 남은 위험

| 위험 | 지금 | 다음에 할 수 있는 것 |
| --- | --- | --- |
| 다른 말투의 숨은 지시 | 정해 둔 모양만 잡는다. 정상 자료 19,206 + 767개에서 오탐은 0이다 | 레드팀 문항을 늘리며 모양을 보강한다. 판정 모델은 비용 대비 효과를 잰 뒤에 넣는다 |
| 근거 평가가 실패할 때 | 상위 문서로 답한다(fail-open, `_grade`) | 의료 정보라 보류로 바꿀지 판단한다. 평가 실패는 Langfuse ERROR로 보인다 |
| 여러 턴에 나눠 보낸 공격 | 라우터가 대화 기록을 읽는다. 가드레일 세트 여러 턴 문항으로 잰다 | 입력 판정이 앞선 질문을 함께 읽게 한다(교안의 Jev 입력 층 방식) |
| 반려견 정보 칸의 지시 | 프롬프트의 구조적 방어로 4/4 막았다 | 같은 정규식을 정보 칸에도 적용할 수 있다 |
| 위기 표현을 놓침 | 정규식 6개(따라가고 싶다, 죽고 싶다, 자해, 살 이유가 없다 등) | 놓친 사례가 나오면 문항과 모양을 함께 더한다 |

## 5. 넣지 않은 것과 이유

| 교안 도구 | 넣지 않은 이유 |
| --- | --- |
| NeMo Guardrails | 교안 스스로 "층이 많고 자주 바뀌면 NeMo, 한두 개면 함수"라고 한다. 라그도그의 검사는 몇 개뿐이라 함수로 충분하다. 도구 메시지가 섞이면 입력 레일이 건너뛰는 함정도 있다. **2026-10-21 레드팀 68문항으로 쟀다:** 입력 레일(`self check input`)은 공격 18/26을 막았지만 앱이 이미 26/26을 견뎠다. 대신 위기 질문 하나(cri-d2)와 사람 약 질문 둘을 막았다. 위기 질문을 막으면 상담 번호 안내가 사라진다. 질문마다 1.4초(p50), 호출 1번이 붙는다. 출력 레일은 0건을 막았다 |
| Llama Guard 3 1B | bf16만으로 약 2.5GB라 Cloud Run 2GiB에 들어가지 않는다. 2026-10-21 측정: CPU 1스레드에서 질문당 66초, 프로세스 4.6GB. 공격 7/26을 막고 정당한 질문 11개(사람 약 7, 위기 1, 개인정보 2, 정상 1)를 막았다 |
| Prompt Guard 2 86M | 메모리가 수백 MB 늘고, 한국어 주입을 놓친다(교안 5-3). 라그도그의 주입 실패는 "답 끝에 ○○라고 써" 같은 형식 지시였다. 2026-10-21 측정: 공격 8/26, 정당한 질문 오차단 0, 질문당 0.44초(CPU 1스레드), torch를 포함한 프로세스 1.7GB |
| Jev(TypeSafe) | 유료 공급자가 하나 늘어난다. 라우터 비교(Day 49)에서 결과가 날짜마다 바뀌었다 |
| Guardrails AI | 개인정보와 링크 검사는 정규식 몇 줄이고, 이미 `src/pii.py`에 있다 |
| 사람 승인, 비용 도구 한도, 외부 API 허용 목록 | 모델이 고르는 쓰기·결제·외부 호출 도구가 없다 |
