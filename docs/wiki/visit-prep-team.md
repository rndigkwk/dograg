## 평가: 상담 12개 Langfuse 실험

상담 12개(반려견 10, 그중 응급 4·진료비 질문 2·지역 있음 9 / 고양이·토끼 2)를 데이터셋 `ragdog-visit-prep-12`로 올려 실험으로 돌립니다(`scripts/langfuse_experiments.py run visit`).

| 지표 | 기준선 (#35 그대로) | 개선 후 (`speed-v1`) |
| --- | ---: | ---: |
| 반려견 상담 검수 통과율 | 0.70 (7/10) | **1.00 (10/10)** |
| 사람 확인으로 끝난 비율 | 0.42 (5/12) | **0 (0/12)** |
| 대상 처리 (반려견은 통과, 다른 동물은 사람 확인 또는 "근거 없음") | 0.75 | 0.92 → 문구 보정 후 **1.00** |
| 응급 판정 정확도 | 1.00 (4/4) | 1.00 (4/4) |
| 지역이 있을 때 병원 목록 | 1.00 (9/9) | 1.00 (9/9) |
| 평균 반려·재조사 횟수 | 1.33 | **0.75** |
| 시간 p50 / p90 | 68초 / 104초 | **49초 / 69초** |
| 12개 합계 시간 / 모델 호출 | 966초 / 236회 | **654초 / 195회** |

- **데이터셋을 만들며 찾은 문제:** 혀가 보라색인 호흡 곤란, 배가 부풀고 헛구역질만 하는 위 확장(위염전) 의심 상담을 응급 판정이 놓쳤습니다. 두 패턴을 추가했습니다. AI Hub 질문 19,206개 중 새 패턴에 걸리는 것은 32개이고 모두 청색증 증상 서술이었습니다. 이 판정은 챗봇의 응급 안내에도 쓰입니다.
- **기준선의 실패 원인:** 통과 못 한 반려견 상담 3개(경련, 청색증, 노견 체중 감소)는 검수까지 가지도 못했습니다. 작성자가 도구로 얻을 수 없는 정보(실시간 영업·응급 진료 여부, 보호자의 정확한 위치, 상담 내용 자체의 근거)를 추가 조사로 두 번 요청하다 반복 상한에 닿았습니다. 같은 병원 조사가 4번 반복된 실행도 있었습니다.
- **시간이 어디에 드는가(기준선 트레이스):** 검수가 가장 느렸습니다(중앙값 23초, 주장 20개를 하나씩 대조). 그다음이 반복된 작성과 조사 라운드입니다.
- **고친 것:**
  - 추가 조사는 한 번만: 작성자가 두 번째로 요청하면 슈퍼바이저가 코드로 "있는 근거로 쓰고 없는 건 '확인할 수 없음'으로" 지시합니다(모델 호출 없음).
  - 작성자 프롬프트에 자료로 알 수 없는 것(영업 여부, 응급 진료 가능 여부, 정확한 위치)을 적고, 재작성 때는 지적된 문장만 고치게 했습니다.
  - 응급 판정과 입력 지역을 검수 근거에 넣었습니다(전에는 "응급 징후가 의심된다"는 문장이 근거 없음으로 반려됨).
  - 병원 조사는 실행당 하나만(도구가 지역만 받으므로 다시 해도 같은 목록).
  - 검수 모델의 추론 강도를 낮춤(`low`): 검수 중앙값 23.0초 → 11.1초.
- **다른 동물:** 고양이·토끼 상담은 이제 반복 상한까지 가지 않고 "반려견 자료로는 확인할 수 없다"고 밝힌 보고서로 통과합니다. 지어낸 내용은 없었습니다. 평가기의 "근거 없음" 문구 목록에 "확인할 수 없"이 빠져 있어 고양이 1건이 처음엔 실패로 집계됐고, 문구를 보정하면 12/12입니다.
- 두 실행은 Langfuse 데이터셋 `ragdog-visit-prep-12`의 Runs에서 문항별로 나란히 볼 수 있습니다.


## 실패 처리 (day56 교안 적용)

| 실패 | 처리 |
| --- | --- |
| 병렬 조사 하나가 오류 | `Send`로 동시에 도는 조사 하나의 예외는 그 단계 전체를 취소해 다른 조사 결과까지 잃는다. 조사 노드가 오류를 `failures`에 기록하고 정상 반환해, 나머지 조사로 계속한다 |
| 무엇이 빠졌나 | 코드가 판단한다. 증상 사례(필수)가 모두 실패하면 `held`: 쓰지 않고 "필수 조사 실패: 수의사(사람) 확인 필요" 보고서를 남김. 병원·진료비(선택)만 실패하면 `degraded`: 그 절을 빼고 쓰며, 보고서 끝에 "수집하지 못한 자료"를 코드로 붙인다 |
| 진료비 조사 실패 → 기본 안내 (폴백) | 진료비 조사가 오류로 실패하거나 근거를 하나도 못 찾으면, 그 절을 비우지 않고 정해 둔 기본 안내(`config.FALLBACK_EVIDENCE`, 근거 id `guide-cost-1·2`)를 조사 결과로 넣는다. 실패 기록은 그대로 남고(`degraded`), 작성자는 "통계를 찾지 못해 기본 안내로 대신합니다"라고 먼저 밝힌다. 기본 안내도 근거라서 검수가 대조하고, 화면 근거 목록에는 "기본 안내 (고정 문구)"로 표시된다 |
| 일시 오류 재시도 | 재시도는 한 계층(OpenAI SDK, `max_retries=2`)에만 둔다. 팀의 외부 호출은 모두 OpenAI라서, 그래프에 `RetryPolicy`를 더하면 시도가 곱해진다(3 × 2 = 6). SDK가 포기한 오류는 위의 실패 기록으로 넘어간다 |
| 핑퐁 | 다시 쓴 보고서에서 지적된 문장이 모두 지난번에 지적된 것과 같으면, 반복 상한을 기다리지 않고 "같은 지적 반복: 수의사(사람) 확인 필요"로 넘긴다 |

- **장애 주입 실험(실제 모델):** 진료비 조사 도구가 연결 오류를 내게 하고 실행했다. 증상 2·병원 1 조사 결과는 그대로 남았고, 보고서는 검수를 통과했으며(근거 있는 주장 13개), 끝에 "수집하지 못한 자료: 진료비 통계"가 붙었다(55초).
- 테스트: 조사 하나 실패 → 나머지 보존, 필수 조사 실패 → 작성 없이 보류, 같은 지적 반복 → 1회 만에 중단, 모델 재시도 계층 하나(`tests/test_visit_team.py`).
- **실패 처리가 잡아낸 배포 장애 (2026-10-08):** 재부팅 직후 배포 앱에서 보고서 페이지로 바로 들어가 실행하자, 증상 조사가 모두 실패해 `held`로 멈췄습니다(Langfuse의 `visit-prep` trace 기록). 원인은 검색 자원(BM25 색인)이 처음 올라오는 곳이 조사원 작업 스레드였던 것입니다. 스피너가 붙은 Streamlit 캐시 로더가 세션 없는 스레드에서 `NoSessionContext`를 냅니다. 같은 조건을 로컬에서 재현(새 서버, 보고서 페이지 직행)해 서버 로그에서 확인했고, 팀을 시작하기 전에 페이지 스레드에서 검색 자원을 먼저 올리도록 고쳐 오류가 사라졌습니다. 다음에 원인을 바로 알 수 있도록 trace 기록에 실패한 예외 종류(`failed_errors`, 메시지는 계속 마스킹)도 남깁니다.
- **정상 실행 회귀 확인(상담 12개 실험 `failure-handling`):** 반려견 통과율 1.00, 대상 처리 12/12, 응급 판정 4/4, 병원 목록 9/9로 그대로이고, 평균 반려·재조사는 0.75 → 0.50회. 시간은 p50 49 → 54초, p90 69 → 83초였습니다. 정상 경로에서 바뀐 것은 작성자 프롬프트 한 줄뿐이고 모델 호출이 늘지 않아(12건 모두 조사 실패 없음) API 응답 시간 편차로 봅니다.

## 노드 방문 횟수와 반복 감시 (day56 과제 1, 2026-10-08)

반복 문제(같은 일을 다시 하는 루프)는 최종 결과만 봐서는 알기 어렵다. 통과한 보고서도 작성자가 세 번 돌았을 수 있다. 그래서 실행마다 **최상위 노드가 몇 번 실행됐는지** 센다.

- **어떻게 세나:** `team.main.run`이 이미 받는 `stream_mode="updates"` 이벤트를 그대로 센다. 최상위 노드 하나가 끝날 때마다 이벤트가 하나 오므로(병렬 조사는 조사마다 하나), 모델 호출을 더하지 않는다. 결과는 `result.json`의 `visits`, Langfuse trace 출력, 실험 출력에 남는다.
- **반복 의심:** 정상 실행이 넘지 않는 횟수(`team/core/config.py`의 `VISIT_LIMITS`)를 넘은 워커. 계획 2(첫 계획 + 추가 조사 한 번), 작성·검수 2(첫 초안 + 다시 쓰기 한 번), 조사는 작업 상한(5 + 2). 슈퍼바이저는 워커가 끝날 때마다 돌기 때문에 횟수가 워커를 따라가므로 뺀다(교안과 같음). 반복 상한(`MAX_ROUNDS`)과 핑퐁 감지가 실제로 멈추는 장치라면, 이 값은 거기 닿기 전에 경향을 보는 경보다.
- **측정(상담 12개 실험 `visit-counts`):** 반려견 통과율 1.00, 대상 처리 1.00, 응급 4/4, 병원 9/9, 시간 p50 46초 / p90 66초로 그대로. 평균 노드 방문 9.25회. 반복 의심 2/12:
  - v11(응급, 반려견): 검수 반려 두 번 → 작성·검수 각 3회. 결국 통과.
  - v03(고양이): 작성자가 추가 조사를 요청 → 한 번 더 요청 → 슈퍼바이저가 "있는 자료로 쓰라"고 돌려보내 작성 3회. 반려견 자료가 없는 상담이라 예상된 경로다.
- **정기 평가에 추가:** 매주 회귀 평가가 이 12개를 함께 돌리고, 반복 의심 비율이 0.34(12개 중 5개)를 넘으면 실패로 알린다. 기준선(#35, 평균 반려·재조사 1.33회, 사람 확인 5/12) 같은 상태로 돌아가면 걸리는 값이다. 테스트 `tests/test_visit_team.py`(`VisitCountTests`), `tests/test_check_regression.py`.

## 보호자에게 되묻기 (day51 interrupt, 2026-10-08)

보고서의 질은 상담 내용에 달려 있다. "말티즈가 설사를 해요"만으로는 언제부터·몇 번·무엇을 먹었는지를 모르고, 수의사가 가장 먼저 물을 것이 보고서에서 빠진다. 그래서 앱에서는 팀이 **계획 전에 멈추고 보호자에게 묻는다**.

- **흐름:** `clarify`(모델 1회: 빠진 정보를 묻는 질문 0~3개) → `ask_guardian`(질문이 있으면 `interrupt`로 멈춤) → 보호자가 답하거나 건너뜀 → 같은 `thread_id`로 `Command(resume=답변)` → `planner`부터 이어서 실행.
- **두 노드로 나눈 이유:** 재개하면 멈춘 노드가 처음부터 다시 실행된다(교안 02). 질문 만들기(모델 호출)와 `interrupt`를 한 노드에 두면 재개할 때 모델을 다시 부르고 질문이 바뀔 수 있다. 그래서 `ask_guardian`에는 모델 호출이 없다.
- **코드로 정한 것:** 응급 상담은 묻지 않는다(응급 판정 결과가 있으면 `clarify`가 모델을 부르지 않음). CLI·실험·정기 평가는 묻지 않는다(`ask=False`, 기존 경로 그대로). 답변은 300자까지, 상담 내용 뒤에 "(보호자 추가 답변)"으로 붙어 계획·작성·검수가 모두 근거로 쓴다.
- **앱:** 체크포인터는 서버 메모리의 `InMemorySaver` 하나(`st.cache_resource`). 멈춘 실행에는 상담 문장이 들어 있어 디스크에 쓰지 않는다. 실행이 끝나거나 새 상담으로 바뀌면 그 thread를 지운다. 답하기는 새 실행으로 세지 않는다(세션당 2회 제한 그대로). 답하지 않고 창을 닫은 실행은 30분 뒤 다음 페이지 방문 때 지운다(멈춘 시각을 서버 전체 목록에 기록, 2026-10-08 추가). 만료되었거나 서버가 재시작돼 이어 갈 실행이 없으면, 보호자에게 다시 만들라고 안내하고 쓴 횟수를 돌려준다.
- **측정:**
  - 질문 결정(상담 12개, `scripts/evaluate_clarify.py`): 8개가 질문을 받음(평균 2.6개), 응급 4개는 0개, 최대 3개, 판단 시간 중앙값 4.1초. 질문 예: "어느 쪽 뒷다리를 들고 걷나요?", "'숨는데'는 몸을 숨긴다는 뜻인가요, 숨쉬기 힘들다는 뜻인가요?"(고양이 상담의 모호한 표현을 짚음). 진단·검사를 권하는 질문은 없었다.
  - 실제 모델 왕복(푸들 귀 긁음 + 마포구): 9초 만에 질문 3개로 멈춤 → 답변("사흘 전부터, 오른쪽 귀 냄새, 갈색 귀지, 7살 4kg")으로 재개 → 계획의 검색어가 "토이푸들 귀 긁기 머리 흔들기 갈색 귀지 냄새"가 되었고 보고서가 답변 내용을 [상담 내용]으로 인용, 검수 통과(52초).
  - 로컬 앱(브라우저): 질문 표시 → 답하고 만들기 → "검수 통과 · 다시 쓰기 0회 · 54초 · 보호자 답변 반영", 남은 횟수 1번(답하기는 세지 않음), 서버 오류 없음.
- 테스트: 멈춤 → 같은 thread로 재개, 빈 답변 = 건너뛰기, 질문 없으면 멈추지 않음, 응급·`ask=False`는 모델 호출 없음(`tests/test_visit_team.py`), 페이지에서 질문 표시·답하기·건너뛰기(`tests/test_visit_prep_page.py`).

## 진료비 조사 폴백 (day56 과제 2, 2026-10-08)

교안 과제 2는 보상액 계산이 실패하면 기본 보상액으로 이어 가고 "담당자 확인" 표시를 남긴다. 우리 팀에서 같은 자리는 **진료비 조사**다. 선택 조사라 실패해도 보고서는 나가지만, 이전에는 그 절이 "이번에는 이 자료를 모으지 못했다" 한 줄로 비었다. 보호자가 비용을 물은 상담이면 가장 궁금한 절이 빈 셈이다.

- **무엇으로 채우나:** 통계를 지어내지 않는 고정 문구 두 개. (1) 진료비는 병원과 검사·처치 항목에 따라 다르니 방문 전에 전화로 진찰료와 예상 검사 비용을 물어볼 것, (2) 동물병원은 주요 진료비를 병원 안에 게시해야 함(수의사법 진료비 게시제). 금액은 넣지 않았다. 틀린 금액보다 확인 방법이 안전하다.
- **언제:** 진료비 조사가 오류로 실패했을 때(실패 기록 + 기본 안내), 그리고 오류는 없지만 근거를 하나도 못 찾았을 때(기본 안내만, 결과는 `complete`). 병원 목록에는 폴백이 없다. 지역 병원을 대신할 고정 문구가 없기 때문이다.
- **기록:** `result.json`과 Langfuse 실행 기록에 `fallback_kinds`.
- **장애 주입 실험(실제 모델, 진료비를 물은 상담 + 강남구):**

| 주입 | 결과 | 검수 | 진료비 절 |
| --- | --- | --- | --- |
| 진료비 도구가 연결 오류 | `degraded`, 실패 기록 `ConnectionError` | 통과, 근거 있는 주장 17개 | "통계를 찾지 못해 기본 안내로 대신합니다" + 기본 안내 2문장 |
| 진료비 도구가 "근거 없음" | `complete` | 통과, 14개 | 같음 |

- 보고서 끝에는 코드가 "수집하지 못한 자료: 진료비 통계(조사 중 오류, 기본 안내로 대신함)"를 붙인다(오류일 때).
- **정상 경로:** 상담 12개 실험(`visit-counts`)에서 진료비 조사 3건은 모두 근거 2~3개를 찾아 폴백이 쓰이지 않았다. 정상 실행에서 바뀐 것은 작성자 입력의 "[기본 안내로 대신한 자료] 없음" 한 줄뿐이다.
- 테스트: 실패 → 기본 안내 + 실패 기록, 병원 실패에는 폴백 없음, 근거 없음 → 기본 안내(실패 아님), 근거 목록 표시(`tests/test_visit_team.py`).


## 진료비 통계 도구 추가 뒤 재측정 (2026-10-10)

#82에서 진료비 조사원에게 지역 진료비 도구(`regional_fee_stats`)를 주고, 조사원이 지역과 반려견 정보를 받게 했다. 그때는 실제 실행 2번으로만 확인했다. 그래서 상담 12개를 다시 쟀다. 같은 날 #82 이전 코드(`2564db15`)도 함께 돌려 API 응답 시간 차이를 줄였다.

- **새 지표**(`scripts/langfuse_experiments.py`):
  - **지역 통계 인용:** 비용을 묻고 지역을 준 상담(v01 강남구 병원비, v09 수성구 검사비)의 보고서가 그 지역의 `fee-` 근거를 인용했는가.
  - **금액 일치:** `fee-` 근거를 인용한 줄의 금액이 모두 인용한 조사 행의 중간·평균·최저·최고 중 하나인가. 지어내거나 섞은 금액을 잡는다.
  - **지역 일치:** 인용한 진료비가 모두 입력 지역이나 전국 값인가.
  - **근거 없는 문장 수 평균**도 함께 본다.

- **#82 이전에는 금액이 없었다.** 진료비 조사원이 보고서 PDF만 찾을 수 있었다. v01·v09 모두 "항목별 예상 비용은 찾지 못했다"로 끝났다.
- **찾은 문제 1: 조사 결과를 버린 조사원 (v01).**
  - 진료비 조사원이 강남구 초진·혈액검사·엑스레이 통계를 이미 받아 놓고도 "호출 상한"으로 실패 처리됐다. 그래서 기본 안내로 대체됐다.
  - 실제로는 상한이 아니었다. API가 추론 2,441토큰 뒤 `status: incomplete`(`max_messages`)로 답 없이 끝난 것이다.
  - 이 조사원만 19번 돌려 4번 재현했다(약 5번에 1번).
  - **고친 것:** 남은 호출이 있는데 답이 없으면, 받은 결과로 정리하라고 한 번만 다시 묻는다(`config.ANSWER_NUDGE`). 그래도 없으면 "호출 상한"이 아니라 `NoAnswer (incomplete: max_messages)`로 기록한다.
- **찾은 문제 2: 다른 지역 통계 인용 (v06).**
  - 해운대구 상담 보고서가 대구광역시 진료비를 인용했다. 진료비 도구가 "해운대구" 안의 "대구"를 시·도 이름으로 읽었기 때문이다.
  - 처음 만든 금액 일치 지표는 이것을 정답으로 셌다. 인용한 행과 금액이 서로 맞았기 때문이다. 그래서 지역 일치 지표를 더했다.
  - 고친 것은 #85에 있다. 마지막 실행에서는 v06이 진료비를 조사하지 않았다. 그래서 수정은 도구 직접 호출(해운대구 → 부산 해운대구 행)과 테스트로 확인했다.
- **v08 (지역 없음, 비용 질문 없음):** #82~#84 실행에서 작성자가 추가 비용 조사를 요청했고, 근거 없는 일반 문장("체중이나 병원에 따라 다를 수 있다")으로 두 번 반려돼 사람 확인으로 끝났다. 나머지 두 실행에서는 바로 통과했다. 실행 1번씩이라 #82의 영향인지는 가를 수 없다.
- **한계:** 조건마다 실행이 1번씩이다. 시간과 반려 횟수의 차이는 API 응답 편차 안에 있다(#35 이후 같은 상담 12개의 p50이 46~54초 사이).
