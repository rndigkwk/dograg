## 평가: 상담 12개 Langfuse 실험

상담 12개(반려견 10, 그중 응급 4·진료비 질문 2·지역 있음 9 / 고양이·토끼 2)를 데이터셋 `ragdog-visit-prep-12`로 올려 실험으로 돌립니다(`scripts/langfuse_experiments.py run visit`).

| 지표 | 기준선 (#35 그대로) | 개선 후 (`speed-v1`) |
| --- | ---: | ---: |
| 반려견 상담 검수 통과율 | 0.70 (7/10) | **1.00 (10/10)** |
| 사람 확인으로 끝난 비율 | 0.42 (5/12) | **0 (0/12)** |
| 대상 처리 (반려견은 통과, 다른 동물은 사람 확인 또는 "근거 없음") | 0.75 | 0.92 → 문구 보정 후 **1.00** |
| 응급 판정 정확도 | 1.00 (4/4) | 1.00 (4/4) |
| 지역이 있을 때 병원 목록 | 1.00 (9/9) | 1.00 (9/9) |
| 평균 반려·재조사 횟수 | 1.33 | **0.75** |
| 시간 p50 / p90 | 68초 / 104초 | **49초 / 69초** |
| 12개 합계 시간 / 모델 호출 | 966초 / 236회 | **654초 / 195회** |

- **데이터셋을 만들며 찾은 문제:** 혀가 보라색인 호흡 곤란, 배가 부풀고 헛구역질만 하는 위 확장(위염전) 의심 상담을 응급 판정이 놓쳤습니다. 두 패턴을 추가했습니다. AI Hub 질문 19,206개 중 새 패턴에 걸리는 것은 32개이고 모두 청색증 증상 서술이었습니다. 이 판정은 챗봇의 응급 안내에도 쓰입니다.
- **기준선의 실패 원인:** 통과 못 한 반려견 상담 3개(경련, 청색증, 노견 체중 감소)는 검수까지 가지도 못했습니다. 작성자가 도구로 얻을 수 없는 정보(실시간 영업·응급 진료 여부, 보호자의 정확한 위치, 상담 내용 자체의 근거)를 추가 조사로 두 번 요청하다 반복 상한에 닿았습니다. 같은 병원 조사가 4번 반복된 실행도 있었습니다.
- **시간이 어디에 드는가(기준선 트레이스):** 검수가 가장 느렸습니다(중앙값 23초, 주장 20개를 하나씩 대조). 그다음이 반복된 작성과 조사 라운드입니다.
- **고친 것:**
  - 추가 조사는 한 번만: 작성자가 두 번째로 요청하면 슈퍼바이저가 코드로 "있는 근거로 쓰고 없는 건 '확인할 수 없음'으로" 지시합니다(모델 호출 없음).
  - 작성자 프롬프트에 자료로 알 수 없는 것(영업 여부, 응급 진료 가능 여부, 정확한 위치)을 적고, 재작성 때는 지적된 문장만 고치게 했습니다.
  - 응급 판정과 입력 지역을 검수 근거에 넣었습니다(전에는 "응급 징후가 의심된다"는 문장이 근거 없음으로 반려됨).
  - 병원 조사는 실행당 하나만(도구가 지역만 받으므로 다시 해도 같은 목록).
  - 검수 모델의 추론 강도를 낮춤(`low`): 검수 중앙값 23.0초 → 11.1초.
- **다른 동물:** 고양이·토끼 상담은 이제 반복 상한까지 가지 않고 "반려견 자료로는 확인할 수 없다"고 밝힌 보고서로 통과합니다. 지어낸 내용은 없었습니다. 평가기의 "근거 없음" 문구 목록에 "확인할 수 없"이 빠져 있어 고양이 1건이 처음엔 실패로 집계됐고, 문구를 보정하면 12/12입니다.
- 두 실행은 Langfuse 데이터셋 `ragdog-visit-prep-12`의 Runs에서 문항별로 나란히 볼 수 있습니다.


## 실패 처리 (day56 교안 적용)

| 실패 | 처리 |
| --- | --- |
| 병렬 조사 하나가 오류 | `Send`로 동시에 도는 조사 하나의 예외는 그 단계 전체를 취소해 다른 조사 결과까지 잃는다. 조사 노드가 오류를 `failures`에 기록하고 정상 반환해, 나머지 조사로 계속한다 |
| 무엇이 빠졌나 | 코드가 판단한다. 증상 사례(필수)가 모두 실패하면 `held`: 쓰지 않고 "필수 조사 실패: 수의사(사람) 확인 필요" 보고서를 남김. 병원·진료비(선택)만 실패하면 `degraded`: 그 절을 빼고 쓰며, 보고서 끝에 "수집하지 못한 자료"를 코드로 붙인다 |
| 일시 오류 재시도 | 재시도는 한 계층(OpenAI SDK, `max_retries=2`)에만 둔다. 팀의 외부 호출은 모두 OpenAI라서, 그래프에 `RetryPolicy`를 더하면 시도가 곱해진다(3 × 2 = 6). SDK가 포기한 오류는 위의 실패 기록으로 넘어간다 |
| 핑퐁 | 다시 쓴 보고서에서 지적된 문장이 모두 지난번에 지적된 것과 같으면, 반복 상한을 기다리지 않고 "같은 지적 반복: 수의사(사람) 확인 필요"로 넘긴다 |

- **장애 주입 실험(실제 모델):** 진료비 조사 도구가 연결 오류를 내게 하고 실행했다. 증상 2·병원 1 조사 결과는 그대로 남았고, 보고서는 검수를 통과했으며(근거 있는 주장 13개), 끝에 "수집하지 못한 자료: 진료비 통계"가 붙었다(55초).
- 테스트: 조사 하나 실패 → 나머지 보존, 필수 조사 실패 → 작성 없이 보류, 같은 지적 반복 → 1회 만에 중단, 모델 재시도 계층 하나(`tests/test_visit_team.py`).
- **실패 처리가 잡아낸 배포 장애 (2026-10-08):** 재부팅 직후 배포 앱에서 보고서 페이지로 바로 들어가 실행하자, 증상 조사가 모두 실패해 `held`로 멈췄습니다(Langfuse의 `visit-prep` trace 기록). 원인은 검색 자원(BM25 색인)이 처음 올라오는 곳이 조사원 작업 스레드였던 것입니다. 스피너가 붙은 Streamlit 캐시 로더가 세션 없는 스레드에서 `NoSessionContext`를 냅니다. 같은 조건을 로컬에서 재현(새 서버, 보고서 페이지 직행)해 서버 로그에서 확인했고, 팀을 시작하기 전에 페이지 스레드에서 검색 자원을 먼저 올리도록 고쳐 오류가 사라졌습니다. 다음에 원인을 바로 알 수 있도록 trace 기록에 실패한 예외 종류(`failed_errors`, 메시지는 계속 마스킹)도 남깁니다.
- **정상 실행 회귀 확인(상담 12개 실험 `failure-handling`):** 반려견 통과율 1.00, 대상 처리 12/12, 응급 판정 4/4, 병원 목록 9/9로 그대로이고, 평균 반려·재조사는 0.75 → 0.50회. 시간은 p50 49 → 54초, p90 69 → 83초였습니다. 정상 경로에서 바뀐 것은 작성자 프롬프트 한 줄뿐이고 모델 호출이 늘지 않아(12건 모두 조사 실패 없음) API 응답 시간 편차로 봅니다.

## 노드 방문 횟수와 반복 감시 (day56 과제 1, 2026-10-08)

반복 문제(같은 일을 다시 하는 루프)는 최종 결과만 봐서는 알기 어렵다. 통과한 보고서도 작성자가 세 번 돌았을 수 있다. 그래서 실행마다 **최상위 노드가 몇 번 실행됐는지** 센다.

- **어떻게 세나:** `team.main.run`이 이미 받는 `stream_mode="updates"` 이벤트를 그대로 센다. 최상위 노드 하나가 끝날 때마다 이벤트가 하나 오므로(병렬 조사는 조사마다 하나), 모델 호출을 더하지 않는다. 결과는 `result.json`의 `visits`, Langfuse trace 출력, 실험 출력에 남는다.
- **반복 의심:** 정상 실행이 넘지 않는 횟수(`team/core/config.py`의 `VISIT_LIMITS`)를 넘은 워커. 계획 2(첫 계획 + 추가 조사 한 번), 작성·검수 2(첫 초안 + 다시 쓰기 한 번), 조사는 작업 상한(5 + 2). 슈퍼바이저는 워커가 끝날 때마다 돌기 때문에 횟수가 워커를 따라가므로 뺀다(교안과 같음). 반복 상한(`MAX_ROUNDS`)과 핑퐁 감지가 실제로 멈추는 장치라면, 이 값은 거기 닿기 전에 경향을 보는 경보다.
- **측정(상담 12개 실험 `visit-counts`):** 반려견 통과율 1.00, 대상 처리 1.00, 응급 4/4, 병원 9/9, 시간 p50 46초 / p90 66초로 그대로. 평균 노드 방문 9.25회. 반복 의심 2/12:
  - v11(응급, 반려견): 검수 반려 두 번 → 작성·검수 각 3회. 결국 통과.
  - v03(고양이): 작성자가 추가 조사를 요청 → 한 번 더 요청 → 슈퍼바이저가 "있는 자료로 쓰라"고 돌려보내 작성 3회. 반려견 자료가 없는 상담이라 예상된 경로다.
- **정기 평가에 추가:** 매주 회귀 평가가 이 12개를 함께 돌리고, 반복 의심 비율이 0.34(12개 중 5개)를 넘으면 실패로 알린다. 기준선(#35, 평균 반려·재조사 1.33회, 사람 확인 5/12) 같은 상태로 돌아가면 걸리는 값이다. 테스트 `tests/test_visit_team.py`(`VisitCountTests`), `tests/test_check_regression.py`.
