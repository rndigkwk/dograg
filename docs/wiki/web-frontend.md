# 웹 앱(Next.js) 첫 화면 무게

웹 앱은 Vercel에 정적 페이지로 올라가고, 답은 브라우저가 API(Cloud Run)에서 직접 받는다(ADR-0008).
화면이 늦게 뜨는 원인은 두 가지뿐이다. 페이지마다 처음 받는 JS와 홈 사진이다.

## 2026-10-23: 마크다운은 답이 올 때, 사진은 보이는 크기로

**측정 (운영 홈, 앱 안 브라우저):** HTML 5KB, TTFB 53ms, JS 청크 172KB(전송량).
홈 사진 3장이 357KB였다. Unsplash 링크가 `w=1200`만 주고 있었다. 세로 사진 원본(1200x1924)이 약 440px 너비의 4:3 틀로 그대로 왔다.

**`next build`의 First Load JS:** 마크다운(`react-markdown` + `remark-gfm`)을 쓰는 페이지만 무거웠다.

| 페이지 | 전 | 후 |
| --- | ---: | ---: |
| `/chat` | 232 kB | **188 kB** |
| `/reports` | 222 kB | **178 kB** |
| `/visit-prep` | 230 kB | **184 kB** |
| 나머지 페이지 | 104~179 kB | 같음 |

- **마크다운:** `components/Markdown.tsx`가 `MarkdownBody`를 `React.lazy`로 따로 받는다. 마크다운은 답이 온 뒤에만 그린다. 묶음이 오기 전에는 같은 글을 줄바꿈만 살려 보여 준다.
- **홈 사진:** `components/HeroImage.tsx`가 Unsplash에서 4:3으로 잘라 480·800·1200px 중 화면에 맞는 것을 받는다(`srcset`, `sizes`). 첫 사진만 `fetchPriority=high`이다. 로컬 확인(창 1024px, 배율 1.25): 사진 4번 요청 138KB(전 357KB). 미리 받기가 480px을 한 번 더 받는다(20KB).
- 바꾸지 않은 것: Supabase 로그인 라이브러리(로그인 화면들의 약 65kB)는 첫 화면에서 로그인 상태를 알아야 해서 그대로 둔다. Next 이미지 최적화는 Vercel 사용량이 들고 Unsplash가 이미 크기를 맞춰 준다.

## 2026-10-23: Lighthouse 전 페이지 점검, 대비와 채팅 흔들림

운영 9개 페이지를 Lighthouse 13.5(모바일)로 쟀다.

| 페이지 | 성능 | 접근성 | 모범 사례 | LCP | CLS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 홈 | 93 | 100 | 100 | 2.7초 | 0 |
| 채팅 | 88 | **95** | 100 | 3.0초 | **0.123** |
| 시설 | 91 | 100 | 100 | 3.0초 | 0.073 |
| 진료비 | 89 | **96** | 100 | 3.1초 | 0 |
| 데이터·관리 일정·보고서·방문 준비·기억 | 90~97 | 100 | 100 | 2.0~3.4초 | 0 |

- **대비:** 보조 글자색 `#66728d`가 연한 보라·베이지 바탕에서 4.22~4.25로 기준 4.5에 못 미쳤다. `#5f6b86`(흰 바탕 5.3, 연한 바탕 4.7 이상)으로 바꿨다.
- **채팅 흔들림:** 첫 방문 저장 안내는 브라우저 기록을 읽어야 보일지 정해진다. 그래서 첫 화면이 그려진 뒤 대화 영역 위에 끼어들어 대화 전체를 밀었다. 안내를 첫 인사 문구 아래(대화 영역 안)로 옮겼다. 로컬 빌드에서 CLS 0.123 → 0, 채팅·진료비 접근성 100.
- **검색 노출(SEO 60):** Vercel이 `*.vercel.app` 주소에 `X-Robots-Tag: noindex`를 붙인다. 앱 코드 문제가 아니다. 노출할지는 소유자가 정한다(직접 도메인 연결).
- **LCP 2~3.4초:** 대부분 글자가 그려지기까지의 지연(element render delay)이다. 점수가 이미 88 이상이라 손대지 않았다.

## 2026-10-23: 대기·오류 화면

- **전:** 기다리는 동안 "⏳ 질문을 확인하고 있습니다…" 한 줄만 보였다. API가 잠에서 깨는 첫 질문(15~27초) 동안 왜 늦는지, 얼마나 기다렸는지 알 수 없었고 멈출 수도 없었다. 실패하면 인터넷이 끊겼든 서버가 실패했든 "잠시 뒤 다시 질문해 주세요" 하나였고, 같은 질문을 다시 쳐야 했다.
- **후 (`components/Waiting.tsx`, `lib/failure.ts`):**
  - 대기 줄에 경과 초를 보여 준다.
  - 8초가 지나도 API가 아무 단계도 알리지 않았으면 "처음 질문은 서버를 깨우느라 20초쯤 걸릴 수 있습니다"를 덧붙인다. 60초가 넘으면 "평소보다 오래 걸린다"고 알린다.
  - 채팅에는 3초 뒤 **멈추기** 버튼이 생긴다.
  - 실패 문구는 원인별로 나눈다: 연결 끊김(오프라인, fetch 실패) / 서버 오류(5xx) / 그 밖은 페이지의 원래 문구.
  - 채팅의 실패·멈춘 답에는 **같은 질문 다시 보내기**가 있다. 실패한 시도는 대화에 남기지 않고 바꿔 넣는다.
  - 데이터·진료비·시설 페이지는 불러오기 실패에 **다시 시도** 버튼이 있다.
- **확인:** vitest `lib/failure.test.ts`. Playwright `e2e/waiting.spec.ts`: 503 뒤 다시 보내기, 응답 없는 질문을 멈추기.

## 2026-10-24: 메뉴 4묶음과 A안 색 (리디자인 1단계)

- **문제:** 최상위 메뉴가 10개라 데스크톱에서도 가로 스크롤이 생기고 "관리 일정"이 잘렸다. 휴대폰에서는 대부분 화면 밖이었다. 아이콘은 이모지라 운영체제마다 모양이 달랐다.
- **결정:** 리디자인 시안의 A안(차분한 진료실). 메뉴는 `lib/nav.ts` 한 표에서 나온다.
  - **상담:** 질병 문의, 방문 준비 보고서, 보고서 질문
  - **찾기:** 시설 찾기, 지역별 진료비
  - **우리 아이:** 관리 일정, 상담 기억
  - **소개:** 데이터 소개
  - 데스크톱은 상단에 묶음별 펼침 메뉴를 둔다(Esc·바깥 클릭으로 닫힘).
  - 휴대폰은 하단 탭(홈·상담·찾기·우리 아이)을 두고, 소개는 상단 링크로 간다.
  - 여러 페이지가 있는 묶음은 페이지 위에 하위 탭 줄이 있다.
- **색:** 강조색 짙은 청록 `#0f6e63`, 바탕 `#f5f8f7`, 보조 글자 `#4f6560`. 모든 글자색이 바탕·흰색·옅은 강조 바탕에서 4.5:1 이상이다(보조 5.1+, 강조 5.0+, 흰 글자 on 강조 6.1).
- **아이콘:** `components/Icon.tsx`. 선 아이콘 몇 개를 직접 넣었고, 의존성은 추가하지 않았다.
- **확인:** vitest `lib/nav.test.ts`(옛 메뉴의 페이지가 모두 한 묶음에 있는지). Playwright는 메뉴로 이동하는 두 테스트를 휴대폰(하단 탭)과 데스크톱(펼침 메뉴)으로 고쳤다(`e2e/nav.ts`).

## 2026-10-24: 홈은 질문 먼저 (리디자인 2단계)

- **전:** 큰 문구("데이터로 지키는 따뜻한 동행")와 사진, 통계 카드가 먼저 나왔다. 질문하려면 "지금 질문하기"를 눌러 상담 화면으로 가서 다시 입력해야 했다.
- **후:**
  - 맨 위에 질문창과 예시 질문 3개를 둔다(`components/HomeAsk.tsx`). 입력하면 상담 화면이 열리고 그 질문을 바로 묻는다.
  - 그 아래에 바로가기 4개(시설 찾기, 지역별 진료비, 관리 일정, 방문 준비 보고서)를 둔다.
  - 사진은 데스크톱에서만 보인다. 통계는 데이터 소개 페이지에 있다.
- **질문 넘기기:** 홈의 질문은 주소(URL)가 아니라 이 탭의 sessionStorage로 넘긴다(`lib/chat.ts` `askLater`/`takeAsked`). 질문에 건강 정보나 개인정보가 담길 수 있고, 주소에 넣으면 방문 기록과 서버 로그에 남는다. 상담 화면은 기록을 읽은 뒤 한 번만 묻고 꺼낸 값을 지운다. 그래서 새로고침해도 다시 묻지 않는다.
- **대비:** 질문창 테두리 `#79948e`(흰 바탕 3.3:1, 입력란 테두리 기준 3:1 이상).
- **확인:** vitest(한 번만 꺼냄, 1,000자 자르기, 저장소 막힘). Playwright: 홈에서 입력한 질문이 상담 화면에서 한 번만 물어지고 주소에 남지 않음, 예시 질문 버튼.

## 2026-10-24: 화면 안의 이모지도 선 아이콘으로 (리디자인 3단계)

- 위치 버튼 📍, 피드백 👍/👎, 상담 기억 🗂, 대기 ⏳, 응급 병원 🚨, 보고서 내려받기 📄📝🖨, 우리 아이 정보 🐾를 `components/Icon.tsx`의 선 아이콘으로 바꿨다(locate, thumbUp/Down, bookmark, clock, alert, file/note/printer, heart).
- 아이콘은 글자 옆 장식이라 `aria-hidden`이다. 아이콘만 있는 버튼(👍/👎, 상단 "기억")은 `aria-label`이 이름이다.
- 저장 안내 문구의 "👎 뒤"는 버튼 이름 "‘아쉬워요’ 뒤"로 바꿨다.
- 코드 주석의 👍/👎는 그대로 둔다(화면에 나오지 않는다).
