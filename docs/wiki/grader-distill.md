# 근거 채점기 증류: OpenAI 채점 호출을 작은 cross-encoder로 — **채택하지 않음** (2026-10-26)

건강 답변은 매번 근거 채점 호출 1번을 기다린다(`src/crag.py`의 `grade_documents`, p90 2.4초, 약 2.3k 토큰). 이 호출은 검색 후보 5개 중 쓸 것을 고르고, 하나도 없으면 검색어를 한 번 바꾼 뒤 보류하게 한다. 같은 판단을 질문과 후보를 함께 읽는 작은 한국어 모델(cross-encoder)이 API의 CPU 1개에서 할 수 있는지 쟀다.

- **노트북:** `notebooks/grader_distill_colab.ipynb` (`scripts/build_grader_distill_notebook.py`로 생성), Colab **L4**
- **기록:** MLflow(DagsHub) 실험 `crag-grader-distill`. 모델마다 학습 실행과 ONNX 실행, 그리고 채점기 라벨 교차 검증 실행 `grader-distill`이 있다(bge 리랭커의 첫 실행은 실패해 다시 돌렸다).
- **결과 파일:** `grader_distill_results.json`. 고른 모델(`klue/roberta-small` ONNX int8, 65MB)과 함께 비공개 Hugging Face 모델 `blanden77/ko-grader-dograg`에 있다.
- **OpenAI 호출 0번.** 학습 라벨은 이미 저장된 관련도 채점을 썼다.

## 설계

| 항목 | 내용 |
| --- | --- |
| 학습 | 학습 상담 질문 150개 × 후보 약 22개의 관련도 채점(0/1/2점, `tests/data/health_relevance_train_*.json`). 목표는 1점 이상 |
| 임계값 고르기 (dev) | 검증 질문의 관련도 채점(`health_relevance_100` + 치과). 시험 질문은 뺐다 |
| 시험 | **실제 CRAG 채점기가 고른 결과**: 검증 질문 100개 × 후보 5개(`tests/data/crag_grader_labels.json`, `scripts/make_grader_labels.py`). 채점기가 하나도 고르지 않은 질문은 12개 |
| 입력 | 질문 + 후보 앞 400자(채점기와 같은 길이), 384토큰 |
| 배포 조건 | ONNX int8, CPU 1스레드에서 질문 1개(후보 5개) **p90 1초 이하**. API의 CPU가 1개다 |
| 2단계 | 고른 모델을 채점기 라벨로 다시 학습(질문 단위 5겹 교차 검증). 채점기 라벨을 더 모을 가치가 있는지 보려고 |

**앱 동작을 바꾸는 지표는 질문 단위 판단 일치다.** 하나도 안 고름 → 다시 검색·보류, 하나라도 고름 → 답. 아무것도 거르지 않고 **후보 5개를 모두 쓰는 기준선**이 이미 0.88이다(채점기가 비운 12개만 틀림).

## 결과 (시험: 채점기 결과 100문항)

관련도 채점으로 학습한 뒤(1단계), 시험 지표:

| 모델 | 크기 | 후보 일치 | κ | AUC | 질문 판단 일치 | CPU 1개 p50 / p90 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 기준선: 모두 씀 | - | 0.446 | 0 | 0.50 | **0.88** | 0 |
| KoELECTRA-small | 14M | 0.470 | 0.03 | 0.63 | 0.88 | 0.37 / 0.39초 |
| **klue/roberta-small (고름)** | 68M | 0.578 | 0.19 | 0.67 | 0.80 | 0.81 / 0.86초 |
| klue/roberta-base | 110M | 0.642 | 0.31 | 0.70 | 0.84 | 1.59 / 1.70초 |
| bge-reranker-v2-m3-ko (상한 참고) | 568M | 0.618 | 0.27 | 0.73 | 0.83 | 5.34 / 5.54초 |

- 학습 전(미세조정 없이) 네 모델 모두 거의 전부를 남겼다(κ 0 근처, 판단 일치 0.88 = 기준선).
- 1초 안에 드는 모델 중 가장 나은 `roberta-small`을 골랐다. KoELECTRA는 학습 뒤에도 94%를 남겨 사실상 기준선과 같았다.
- **호출을 줄일 수 있는 비율:** 작은 모델이 확신할 때만 판단하고(채점기와 95% 일치하는 구간) 나머지는 채점기를 부르는 방식으로 셌다. `roberta-small`은 질문의 **3%** 만 대신했고, 그 3개 중 채점기와 같은 후보를 고른 것은 1개였다.

채점기 라벨로 다시 학습한 뒤(2단계, `roberta-small`, 5겹 교차 검증):

| 임계값 | 후보 일치 | κ | AUC | 남긴 비율 | 질문 판단 일치 |
| --- | ---: | ---: | ---: | ---: | ---: |
| dev에서 고른 값 | 0.648 | 0.26 | 0.72 | 0.27 | **0.55** (53개를 비움, 실제 12개) |
| 시험에서 고른 값 (상한, 쓸 수 없음) | 0.680 | 0.37 | 0.72 | 0.55 | 0.78 |

- 채점기 라벨로 다시 학습해도 AUC는 0.67 → 0.72에 그쳤다. 임계값을 시험셋에 맞춰 골라도 판단 일치가 기준선 0.88보다 낮다.

## 결론과 이유

**넣지 않는다.** 채점 호출(p90 2.4초)은 그대로 둔다.

- **앱이 쓰는 판단에서 기준선보다 나쁘다.** 1초 안에 드는 모델 중 가장 나은 것이 질문 판단 0.80이다. "모두 쓴다"는 0.88이고, 이것은 근거 평가가 없던 예전 동작이다. 작은 모델로 바꾸면 보류할 질문을 답하거나 답할 질문을 보류하는 일이 지금보다 많아진다.
- **κ 0.19~0.31은 "채점기를 흉내 낸다"고 말할 수 없는 수준이다.** 같은 채점 두 번의 일치는 κ 0.79였다([judge-validation.md](judge-validation.md)).
- **원인으로 보는 것:**
  - 라벨이 다르다. 학습 라벨은 판사가 후보 22개를 0/1/2로 매긴 관련도이고, 시험은 채점기가 후보 5개 중 "질문의 일부에라도 도움"으로 고른 것이다. 같은 관련도 기준인 dev에서는 κ 0.33~0.57로 더 높았다.
  - 데이터가 적다. 학습 질문 150개, 채점기 라벨 100문항(비운 질문 12개)이다.
  - 채점기는 후보 5개를 함께 보고 상대적으로 고르는데, cross-encoder는 후보를 하나씩 본다.
- **비용을 줄이는 다른 길이 이미 있다.** 자료와 먼 질문은 채점 없이 보류한다([safety-and-evidence.md](safety-and-evidence.md) "자료와 먼 건강 질문"). 채점 호출은 추론을 끄고 돌린다.

## 다시 볼 조건

- 채점기 라벨이 수천 쌍 이상 쌓일 때(운영 트레이스는 질문 글을 가리므로, 평가 세트를 늘려 모아야 한다)
- 채점 호출이 답 지연의 큰 몫이 될 때(지금은 근거를 첫 글자보다 먼저 보여 줘서 체감 대기가 줄었다)
- API에 CPU가 더 붙어 `roberta-base`(κ 0.31, 1.6초)급이 1초 안에 들 때. 이때도 판단 일치가 기준선 0.88을 넘는지부터 본다

## 알게 된 것

- 증류 실험은 **학생 모델이 이겨야 할 기준선**을 먼저 정해야 한다. 후보 단위 정확도(0.45 → 0.58)만 보면 나아진 것 같지만, 앱이 쓰는 질문 단위 판단으로는 "아무것도 하지 않기"보다 나빴다.
- 시험 라벨을 만든 채점기와 학습 라벨을 만든 판사가 다르면, 학생은 판사를 배운다. dev(판사 라벨) κ 0.33 대 시험(채점기 라벨) κ 0.19의 차이가 그것이다.
