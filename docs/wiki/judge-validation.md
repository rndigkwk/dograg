# 판사 검증: LLM 판사를 믿어도 되나 (2026-10-15)

Day 60(LLM-as-Judge) 교안을 우리 판사에 적용한 기록이다. 스크립트는 `scripts/judge_validation.py`, 칸 목록은 `tests/data/judge_validation.json`(번호만, 원문 없음)이다.

## 왜 했나

우리 숫자 중 두 가지는 LLM 판사가 매긴다.

| 판사 | 매기는 것 | 이 숫자로 정한 것 |
| --- | --- | --- |
| 관련성 판사 (`scripts/relevance_set.py`) | 검색 후보가 질문에 쓸모 있는지 0/1/2 | useful@3. KURE-v1 미채택(p=0.008), halfvec 전환, 가벼운 대체 검색, 하이브리드 설정 |
| 답변 판사 (RAGAS `answer_correctness`) | 앱 답이 수의사 답과 맞는 정도 0~1 | 주간 회귀 기준 ≥ 0.25 |

두 판사 모두 **답변 모델과 같은 gpt-6-luna**이고, 사람 판정과 대조한 적이 없었다. 교안의 경고 두 가지가 그대로 해당한다. 판사가 자기 계열 답에 후할 수 있고(자기 선호), 일치율만 높고 실패를 못 잡는 판사일 수 있다(늘 pass 판사).

## 무엇을 쟀나

**칸 고르기 (`sheet`)**
- **관련성 48칸:** 질문마다 한 칸, 판사가 2·1·0을 준 칸을 16개씩 골랐다. 앱이 보여 줄 수 있는 하이브리드 상위 6개 안에서만 골랐다. 늘 2만 주는 판사가 높은 일치율을 얻지 못하도록 고르게 섞었다.
- **답변 30칸:** 주간 평가의 건강 답변(실행 0) 중 `answer_correctness`가 낮은·중간·높은 3분의 1에서 10개씩 골랐다.
- 사람은 `output/judge_validation/label_sheet.html`에서 판사와 **같은 기준 문장**으로 판정한다. 판사 점수는 숨긴다. 결과는 `judge_labels.json`으로 내려받는다.

**판사끼리 비교 (`judge`, 사람 판정 없이 가능)**
- 같은 판사를 같은 순서로 다시: 판정이 흔들리는 정도(기준선)
- 같은 판사를 후보 순서를 뒤집어서: 위치 효과. 관련성 판사는 질문 하나의 후보 24개를 한 번에 채점하므로 순서가 영향을 줄 수 있다.
- 다른 판사(gpt-4.1)로: 자기 선호. 프로젝트에 다른 회사 API 키가 없어 OpenAI의 다른 세대 모델을 썼다.

**편향 점검 (`bias`, `ragas-bias`)**: 답 30개마다 승자를 아는 쌍 세 가지를 만들어 두 순서로 물었다.
- **길이:** 원래 답 vs 원래 답 + 일반 관리 요령 한 문단. 무승부가 정답이다.
- **권위:** 원래 답 vs 원래 답 + "수의사가 직접 검토해 확정한 내용입니다". 무승부가 정답이다.
- **엉뚱한 답:** 원래 답 vs 다른 질문의 답. 원래 답이 이겨야 한다.
- **양방향 규칙:** 두 순서의 승자가 같을 때만 승자로 친다. 다르면 무승부다.

## 결과 (사람 판정 전)

**관련성 판사 48칸**

| 비교 | 0/1/2 그대로 같음 | 가중 kappa | 2와 2 아님이 갈린 칸 |
| --- | ---: | ---: | ---: |
| 같은 판사, 다시 | 0.854 | 0.889 | 4 |
| 같은 판사, 후보 순서 뒤집음 | 0.833 | 0.814 | 4 |
| 다른 판사 (gpt-4.1) | 0.771 | 0.781 | 4 |

- **위치 효과는 흔들림 수준이다.** 순서를 뒤집어도 다시 물을 때와 거의 같다(0.833 vs 0.854). useful@3에 쓰는 "2인가" 판정은 어느 비교에서도 48칸 중 4칸만 바뀌었다.
- **다른 판사와도 대체로 같다(kappa 0.78).** 어긋난 11칸은 대부분 이웃 점수였다(0↔1 7칸, 1↔2 3칸). 2↔0은 1칸뿐이다. gpt-6-luna가 자기 계열이라 크게 후하다는 신호는 없다.

**답변 판사 30칸 (pass/fail 직접 판정)**
- gpt-6-luna는 30개 중 1개, gpt-4.1은 0개를 fail로 봤다. 일치율은 0.967이다.
- fail 1개(a10)는 중성화 시기였다. 수의사는 생후 7개월, 앱은 5~6개월이라고 했다.
- 그런데 같은 30개의 RAGAS 점수는 0.11~0.60에 퍼져 있다.
- 둘 중 하나다. 직접 판정 판사가 너그럽거나, RAGAS가 표현 차이를 깎아 점수가 낮게 나오는 것이다. **어느 쪽인지는 사람 판정으로만 가릴 수 있다.**

**편향 (두 순서 × 30쌍)**

| 쌍 | gpt-6-luna 한 번 판정 | gpt-6-luna 양방향 | gpt-4.1 한 번 판정 | gpt-4.1 양방향 |
| --- | ---: | ---: | ---: | ---: |
| 길이 (무승부가 정답) | 28/30 (긴 답 승 3번/60) | **30/30** | 25/30 (긴 답 승 5번/60) | **30/30** |
| 권위 (무승부가 정답) | 30/30 | 30/30 | 30/30 | 30/30 |
| 엉뚱한 답 (원래 답 승) | 30/30 | 30/30 | 28/30 | 28/30 |

- **길이 효과가 조금 있고, 양방향 판정이 모두 없앴다.** gpt-6-luna가 긴 답을 고른 3번 가운데 2번은 긴 답이 B 자리, 1번은 A 자리였다. gpt-4.1의 5번은 모두 B 자리였다. 어느 경우든 자리를 바꾸면 무승부가 나와, 양방향 규칙으로 무승부가 됐다.
- **권위 문구에는 흔들리지 않았다.**
- **주간 기준의 판사(RAGAS)도 같은 변형으로 쟀다.** 일반 문단을 덧붙이면 평균 0.309 → 0.290, 권위 문장은 0.309 → 0.291이었다. 둘 다 30개 중 과반에서 점수가 내려갔다.
  - 근거 없는 말을 더한 답을 오히려 조금 깎는다. 길게 써서 주간 기준을 통과하는 일은 없다.
  - 내려간 폭(0.02)은 판정 흔들림(0.012)보다 조금 크다.

## 앞으로 쓰는 법

- **프롬프트를 바꿔 답을 비교할 때:** 점수 하나를 비교하지 말고 두 순서로 물어 양방향 규칙을 적용한다(`judge_validation.two_way`, `pair_verdicts`). 한 번만 물으면 30쌍 중 2~5쌍이 길이나 자리 때문에 틀렸다.
- **판사를 바꿀 때:** 같은 48+30칸으로 이 성적표를 다시 낸다. 주간 기준은 판사 이름이 다르면 실패하도록 묶어 두었다(`check_regression.JUDGES`, [observability.md](observability.md)).
- **사람 판정이 들어오면:** `score --labels judge_labels.json`이 다음을 낸다. 아래 절에 결과를 적는다.
  - 판사마다 일치율, kappa, 사람이 "쓸모없음·fail"로 본 칸을 판사가 잡은 비율(실패 탐지율), 사람이 통과로 본 칸을 판사도 통과시킨 비율(정상 통과율)
  - 같은 표에서 늘 "쓸모 있음"·"pass"만 주는 판사의 성적
  - RAGAS 점수의 AUC와 문턱값(0.25~0.40)별 성적표

## 사람 판정 결과

프로젝트 소유자가 78칸을 판사와 같은 기준 문장으로 판정했다(2026-10-15, 판사 점수는 가림). 2026-10-20에 성적표를 냈다. 라벨은 `tests/data/judge_labels.json`(칸 번호와 점수만, 원문 없음)이고, 다시 내려면 `uv run python scripts/judge_validation.py score --labels tests/data/judge_labels.json`(모델 호출 없음)을 쓴다.

**관련성 판사 48칸** (사람: 2가 18, 1이 10, 0이 20)

"쓸모 있음(2)"과 "그렇지 않음"으로 나눠 비교했다.

| 판사 | 0/1/2 같음 | 가중 kappa | 일치율 | kappa | 쓸모없음 잡음 | 쓸모 있음 유지 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| **앱 판사 (gpt-6-luna)** | 0.583 | 0.714 | 0.833 | **0.636** | 0.90 | 0.72 |
| 앱 판사, 다시 | 0.542 | 0.636 | 0.792 | 0.535 | 0.90 | 0.61 |
| 앱 판사, 후보 순서 뒤집음 | 0.562 | 0.677 | 0.833 | 0.628 | 0.93 | 0.67 |
| 다른 판사 (gpt-4.1) | 0.646 | 0.714 | 0.833 | 0.636 | 0.90 | 0.72 |
| 늘 "쓸모 있음" | | | 0.375 | 0 | 0 | 1.00 |

- **믿을 만하다.** kappa 0.64는 "상당한 일치"다. 사람이 쓸모없다고 본 칸의 90%를 판사도 잡는다. 늘 "쓸모 있음"만 주는 판사(0.375)와 확연히 다르다.
- **자기 선호는 보이지 않는다.** 다른 회사가 아닌 다른 세대 모델(gpt-4.1)도 같은 kappa를 냈다.
- **판사가 사람보다 엄하다.** 사람이 쓸모 있다고 본 칸의 28%를 판사는 2로 주지 않았다. 그래서 useful@3의 **절댓값**은 사람 기준보다 낮게 나온다. 같은 판사로 두 방식을 비교하는 결론(KURE 미채택, 의미 검색만 채택 등)에는 영향이 작다.

**답변 판사 30칸** (사람: pass 27, fail 3)

| 판사 | 일치율 | 실패 잡음 | 통과 유지 | kappa |
| --- | ---: | ---: | ---: | ---: |
| 직접 판정 (gpt-6-luna) | 0.867 | **0 / 3** | 0.96 | −0.05 |
| 직접 판정 (gpt-4.1) | 0.900 | 0 / 3 | 1.00 | 0 |
| RAGAS ≥ 0.25 (주간 기준선) | 0.600 | 1 / 3 | 0.63 | −0.02 |
| RAGAS ≥ 0.30 | 0.500 | 2 / 3 | 0.48 | 0.05 |
| RAGAS ≥ 0.35 | 0.333 | 3 / 3 | 0.26 | 0.07 |
| 늘 pass | 0.900 | 0 / 3 | 1.00 | 0 |

- **답변 판사는 실패를 잡지 못한다.** 직접 판정 판사는 사람이 fail로 본 3칸을 하나도 잡지 못했다. 일치율 0.867은 "늘 pass" 판사(0.900)보다 낮다.
- **RAGAS 점수도 사람 판정과 거의 무관하다**(AUC 0.568). 문턱을 올리면 실패는 잡지만 정상 답을 대부분 떨어뜨린다.
- **표본의 한계:** 사람이 fail로 본 칸이 3개뿐이다. 실패 탐지율은 0/3, 1/3처럼 거칠다. 결론은 "답변 판사가 쓸모 있다는 근거가 없다"까지다.
- **바꿔야 할 것:**
  - 주간 기준의 `answer_correctness ≥ 0.25`는 경로가 크게 망가지는 것(0.14)만 잡는 경보로 본다. 품질 판정에 쓰지 않는다.
  - 답변 품질은 사람이 fail로 보는 유형을 모은 뒤 다시 잰다. fail 칸이 15개 이상 되도록 칸을 더 골라야 한다.

## 다른 계열 판사: Claude Haiku 5.5·Opus 5.5 (2026-10-22)

**왜:** 판사가 모두 OpenAI(gpt-6-luna, gpt-4.1)라서, 답변 판사가 사람의 fail을 못 잡는 이유가 자기 계열 답에 후해서인지 가릴 수 없었다. 다른 회사 모델로 같은 칸을 판정했다.

**방법:**
- `scripts/claude_judge.py`: LangChain 구조화 출력 모델과 같은 모양(`invoke([("system", …), ("user", …)])`)으로 Claude를 부른다. 그래서 판정 프롬프트와 집계를 그대로 쓴다. 키는 `.env`의 `CLAUDE`와 `CLAUDE_WORKSPACE_ID`다.
- `uv run --with anthropic python scripts/judge_validation.py claude --claude-model <모델>`: 78칸. `judges.json`에 모델 이름으로 저장한다.
- `… pairs --claude-model <모델>`: 답변 추론 medium 대 low 22쌍([deployment-resources.md](deployment-resources.md) "건강 답변 지연 2")을 두 순서로 묻는다. 두 순서가 같을 때만 승자로 친다. 사람 판정은 `tests/data/answer_effort_labels.json`에 있다.
- 판정이 거절되면(안전 분류기) 판정 없음으로 둔다. 다른 모델로 넘기는 fallback은 쓰지 않았다. 넘기면 어느 모델이 판정했는지 흐려진다. 거절은 0건이었다.
- 호출: 모델마다 122번(78 + 44).

**78칸, 사람 판정 대비:**

| 판사 | 관련성 kappa | 사람이 "쓸모 있음"이라 한 칸을 인정 | 사람이 "쓸모없음"이라 한 칸을 잡음 | 답변 실패 탐지 (3개) |
| --- | ---: | ---: | ---: | ---: |
| gpt-6-luna (지금 판사) | **0.64** | **0.72** | 0.90 | 0/3 |
| gpt-4.1 | 0.64 | 0.72 | 0.90 | 0/3 |
| Claude Haiku 5.5 | 0.28 | 0.39 | 0.87 | 0/3 |
| Claude Opus 5.5 | 0.30 | 0.33 | 0.93 | 0/3 |

**22쌍(사람: low 6, medium 5, 비슷함 11):**

| 판사 | 사람과 일치 | 사람이 승자를 고른 11쌍에서 일치 | 판사의 선택 (medium / low / 비슷함) | 순서 바꾸면 뒤집힘 |
| --- | ---: | ---: | --- | ---: |
| Claude Haiku 5.5 | 9/22 | 7/11 | 12 / 7 / 3 | 0 |
| Claude Opus 5.5 | 8/22 | 5/11 | 7 / 9 / 6 | 0 |

- **관련성은 지금 판사가 사람과 가장 잘 맞는다.** Claude는 두 모델 모두 "바로 쓸모(2)"를 훨씬 엄하게 줬다. 사람이 쓸모 있다고 본 칸의 3분의 2를 쓸모없다고 봤다.
- **답변 판사가 실패를 못 잡는 것은 판사 계열 탓이 아니다.** 다섯 판사(gpt 둘, ragas, Claude 둘) 모두 사람이 fail로 본 3칸(a02·a11·a16)을 통과시켰다. Opus는 세 답 모두 "수의사 판단과 어긋나지 않는다"고 했다. 기준 문장은 "반대 판단만 fail, 더한 내용은 괜찮다"인데, 사람은 핵심이 빠지거나 부족한 답에 fail을 줬다. 다음 일은 판사를 바꾸는 것이 아니라 **기준 문장을 다듬고 fail 칸을 15개 이상 모으는 것**이다.
- **쌍 비교도 사람을 대신하지 못한다.** 두 판사 모두 순서는 일관됐다. 하지만 사람이 "비슷함"으로 본 쌍에서도 한쪽을 골랐고, 서로도 갈렸다(Haiku는 medium 쪽, Opus는 low 쪽). 답변 추론을 low로 바꾼 결정은 사람 판정으로 했다.
- **결정:** Claude 판사를 기준으로 쓰지 않는다. 다른 계열 모델은 아래처럼 문항을 쓰는 데 더 쓸모가 있었다([safety-and-evidence.md](safety-and-evidence.md) "다른 계열이 쓴 레드팀").

## 답변 판정 기준 2와 두 번째 라벨 (2026-10-22, 결과 10-23)

다섯 판사가 모두 사람의 fail 3칸을 놓친 원인은 기준 문장이었다(위 절). 기준 1은 반대되는 판단만 fail로 본다. 사람은 핵심 조치가 빠진 답에도 fail을 줬다.

- **기준 2**(`ANSWER_CRITERION_V2`): 다음 중 하나라도 있으면 fail이다.
  - 수의사의 핵심 판단과 반대된다.
  - 보호자가 꼭 알아야 할 핵심 조치가 빠졌다.
  - 기준 답변에 없는 진단·약·용량을 단정한다.
  - 표현이 다르거나 더 짧다는 것만으로는 fail이 아니다.
- **칸 30개 추가**(`uv run python scripts/judge_validation.py sheet2`, `tests/data/judge_validation_answers2.json`): 이미 라벨한 30칸을 빼고, fail이 나올 법한 답을 골랐다. RAGAS 점수가 가장 낮은 20개와 가장 짧은 10개다. 페이지는 `output/judge_validation/label_sheet2.html`이고, 결과는 `judge_labels2.json`으로 내려받는다.

## 보고서 판사: "뒤집은 비율" 규칙을 넣지 않음 (2026-11-05)

- **계기:** data-v14 holdout에서 h01이 오답으로 판정됐다. 답의 "전체 가입률 11.9%"는 정답의 "미가입 88.1%"를 100%에서 뺀 같은 사실이고, data-v13에서는 같은 근거로 정답이었다([kb-ocr-gpu.md](kb-ocr-gpu.md) "남은 짝 15곳").
- **시험:** 보고서 판사(`evaluate_report_pages.py`, medium) 기준에 한 줄을 더한 안을 지금 기준과 나란히 돌렸다. 더한 줄은 "같은 사실을 다른 쪽에서 나타낸 수치(100%에서 뺀 비율)는 맞음, 대상·단위가 다른 수치는 제외"다. h01과 r08(단위 "마리/명")의 답을 한 번씩 만들고 같은 답을 기준마다 5번 판정했다. 모델 호출은 22번이다.

| 문항 | 지금 기준 | 한 줄 더한 기준 |
| --- | --- | --- |
| h01 | correct 5/5 | correct 5/5 |
| r08 | partial 4, wrong 1 | wrong 5/5 |

- **결정:** 기준을 바꾸지 않는다. h01 오답은 지금 기준에서 드물게 나는 흔들림이었다(5/5 정답). 더한 줄은 h01을 바꾸지 못하고, "단위가 다른 수치" 문구 때문에 r08을 더 엄하게 봤다.
- **쓰는 법:** 보고서 답변 비교에서 한 문항만 바뀌면 그 문항을 다시 판정해 흔들림인지 먼저 본다(위 "앞으로 쓰는 법").
