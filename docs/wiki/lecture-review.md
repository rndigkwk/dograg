## 적용 추천 (우선순위 순)

### 1. CRAG 근거 평가 → 재검색 → 답변 보류 (Day 53-01)

- **해결하는 문제:** 관련도 임계값이 없어서 무관한 질문에도 근거 k건이 붙는다([safety-and-evidence.md](safety-and-evidence.md)).
- **방법:** 검색 뒤 LLM이 근거를 `correct` / `ambiguous` / `incorrect`로 판정한다. 부족하면 검색어를 다시 써서 한 번 더 검색하고, 그래도 없으면 "확인 불가"와 동물병원 안내를 낸다.
- **교안과 다르게 할 점:** 웹 검색 단계를 뺀다. 출처 검증 없는 웹 의료 정보는 "검색 데이터 밖 내용은 추측하지 않음" 원칙과 충돌한다.
- 검증하지 못한 숫자 임계값 대신 LLM 판정을 쓰는 우회로다.

### 2. Cross-Encoder 리랭킹 (Day 48-01)

- 현재 구조(Dense 12 + BM25 12 → RRF → 3)가 교안의 "후보 20 → 리랭킹 → 3~5"와 거의 같다.
- 기각된 n-gram 재정렬은 문자 겹침 기반이었다. Cross-Encoder(`Qwen3-Reranker-0.6B` 등)는 질문과 문서를 함께 읽는 다른 방식이다.
- **선행 조건:** 정답이 후보 풀 안에 있는 비율(후보 재현율)이 hit@3보다 충분히 높아야 한다. 리랭킹은 후보에 없는 문서를 가져오지 못한다. → [retrieval-experiments.md](retrieval-experiments.md) 실험 4
- **위험:** Streamlit Cloud는 CPU 환경이라 24쌍을 점수화하면 응답이 몇 초 늦어질 수 있다.

### 3. 평가 체계 보강 (Day 53: RAGAS, 골드셋)

- 지금 지표는 메타데이터 완전 일치뿐이라 1·2·4번의 효과를 잴 수 없다.
- 근거 충실도(faithfulness), 근거 관련성을 추가한다. 생성 단계 유사도 손실(0.7721 → 0.7448)도 이 지표로 추적할 수 있다.

### 4. Self-RAG 답변 검토 (Day 53-02)

- 초안을 근거성·유용성 기준으로 검토하고, 통과하지 못하면 고치거나 보류한다. 의료 도메인에서 근거 없는 단정을 거르는 데 쓸모가 있다.
- LLM 호출이 2~3회 늘어나므로 1번의 효과를 본 뒤 결정한다.

### 5. LangGraph로 `chatbot()` 재구성 (Day 50)

- Day 50-02의 `classify → retrieve → 근거 유무 분기 → generate / no_evidence / clarify` 구조가 현재 흐름과 거의 같다.
- 1·4번의 순환(재검색, 재검토)을 넣으려면 그래프 구조가 낫고, `pages/rag.py` 분리 과제도 함께 해결된다.

## 맞지 않음

- **Graph + Vector (Day 49):** 관계를 따라가는 멀티홉 질문이 없고, 병원 데이터는 SQL로 충분하다.
- **HITL / 승인 대기 (Day 51):** 일반 사용자용 챗봇이라 사람 승인 단계가 없다.
- **SqliteSaver, Store, Mem0 장기 기억 (Day 51-03, 52):** 로그인이 없어 `user_id`가 없다. 건강 정보와 위치를 서버에 남기는 것은 "좌표를 저장하지 않음" 원칙과 같은 개인정보 문제를 만든다.
- **Jev 라우팅 (Day 47-03, 49-03):** 섀도 테스트에서 정확도가 기존과 같았다([router.md](router.md)).

> **갱신 (2026-10-02, [deployment-resources.md](deployment-resources.md)):** 로컬 리랭커는 Cloud에서 쓸 수 없다. bge-m3 재사용은 질문당 45~145초, Qwen3-Reranker는 최고 메모리 5.1GB에 질문당 13분 이상이 걸렸다. 2번 리랭킹은 로컬 모델 대신 CRAG의 LLM 근거 판정으로 대체하는 방향을 검토한다. 그보다 먼저 임베딩 모델을 하나로 줄여야 한다.
