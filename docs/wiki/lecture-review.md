# 교안 적용 정리 (Day 02~69, 2026-10-28 다시 정리)

엔코아 AI 캠퍼스 교안(`class_1`의 다섯 실습 폴더, `openai-decisions-examples`, `enkoa-practice-deep-learning`)을 Day 순서로 놓고, 각 Day의 내용을 이 프로젝트에 어떻게 썼는지 정리한다. 처음 판(2026-10-09, Day 46~56)과 재검토(2026-10-16), Day 65~69 추가(2026-10-28)를 한 문서로 합쳤다.

- ✅ **적용**: 앱이나 평가·운영 도구에 들어가 있다. 어떻게 넣었고 무엇이 좋아졌는지.
- 🧪 **테스트 후 미적용**: 같은 평가 세트로 재 보고 넣지 않았다. 결과와 이유.
- ➖ **적용 안 함**: 재지 않았다. 맞지 않는 이유.
- 🔜 **할 일**: 해 볼 만하고 아직 하지 않았다. 문서 끝 "할 일"에 모았다.

수치는 모두 같은 평가 세트의 전후 비교다. 자세한 기록은 링크한 문서에 있다.

**교안 폴더에 없는 Day:** 01, 24~26, 43~45. 이 문서에서 다루지 않는다.

**판단의 배경이 바뀐 시점 (2026-10-16):** Day 46~56을 처음 검토한 10-09에는 메모리 약 1GB(Streamlit Cloud)와 "서버에 대화 내용을 남기지 않는다"는 두 제약이 있었다. ADR-0007·0008로 앱이 Cloud Run(2GiB)으로 옮겨 가고 Supabase 저장소와 로그인(RLS로 본인 행만)이 생겼다. 그 두 제약을 이유로 보류했던 항목은 해당 Day 표에 "재검토" 결과를 적었다. Streamlit Cloud 백업 앱(`streamlit-backup` 브랜치)은 여전히 1GB이고, 재검토 뒤의 변경은 백업에 넣지 않는다.

## 지식 그래프 (enkoa-practice-knowledge-graph)

Day 27~42는 Neo4j로 지식 그래프를 만들고 검색하는 단원이다. 이 프로젝트의 자료(건강 Q&A, 보고서, 시설 목록)에는 "증상 → 질병 → 약" 같은 관계 데이터가 없다. 관계를 모델로 뽑으면 그 정확도부터 검증해야 하고, 그래프 DB 하나가 운영에 더 생긴다. 그래서 그래프 자체는 쓰지 않는다(Day 49와 같은 판단). 아래 표는 그래프가 아니어도 같은 생각을 쓴 곳만 ✅로 적었다.

## 딥러닝 (enkoa-practice-deep-learning/내작업)

이 프로젝트는 답변을 API 모델로, 임베딩을 CPU ONNX로 만든다. 그래서 신경망을 직접 짜고 학습하는 내용은 대부분 맞지 않는다. 쓸 만한 것은 **학습 데이터를 다루는 방법**(Day 69)과 **학습 기록·모델 고르기**(Day 66)다.

### Day 66 · CNN, 과적합, 모델 고르기, Lightning

### Day 69 · 학습 데이터 만들기, 품질 검사, 리랭커

| 교안 내용 | 상태 | 어떻게 / 결과 / 이유 |

| 유사 중복 제거, **평가 질문과의 오염 검사** | ✅ | 2026-10-28에 쟀다(`scripts/measure_eval_overlap.py`, 모델 호출 없음). 행은 겹치지 않지만, AI Hub는 같은 상담을 말만 바꿔 두 번 싣고 학습·검증에 하나씩 나눴다. 긴 상담 561개 중 53개(9%)가 말뭉치에 그런 복사본이 있었다. 점수를 매긴 100문항에서는 13문항이 복사본이 있고 13문항 모두 복사본을 상위 3위에 찾았다. 그래서 `useful@3` 0.72는 복사본을 빼면 0.678이다. 손으로 쓴 짧은 질문 120개에는 복사본이 없다([eval-coverage.md](eval-coverage.md) "평가 질문의 복사본") |
| 원본 단위 분할, 데이터 카드 | ✅ / 🔜 | 원본 단위 분할은 Day 66과 같이 이미 한다. 데이터 카드는 미세조정 모델 저장소(Hugging Face 비공개)에 아직 없다. 다음 학습 때 출처·생성 방법·분할·알려진 한계를 함께 올린다 |
| Cross-Encoder 리랭커(Qwen3-Reranker-0.6B) | 🧪 | Day 48에서 같은 모델을 쟀다. 질문당 166초, 메모리 최고 4.9GB라 배포 조건에 맞지 않았다 |
| 부록 · 로컬 LLM(Gemma 4, RunPod)으로 데이터 생성 | ➖ | 합성 데이터는 API로 한 번에 만들었고 비용이 작았다($3.37). GPU 파드를 띄우는 비용과 수고가 더 크다 |
